**Abstract**

**\[AUTHOR: fill in the two bracketed numbers from your own case-study run; everything else below is verified.\]**

Transcriptomic and DNA-methylation studies of immune-mediated disease are usually analysed in isolation, pooled across sexes, and interpreted with command-line pipelines that non-programmers cannot reproduce. ArthOMix is an open-source R Shiny application that addresses these three limitations in one interface. It is organised into four verticals, Transcriptomics, Methylomics, Cross-Omics and Multi-Omics, comprising 45 sub-modules, and every vertical accepts user-uploaded data, data fetched directly from NCBI GEO, or a bundled rheumatoid arthritis (RA) reference cohort, with each intake path isolated so that state never leaks between pipelines. Sex is treated as a first-class variable throughout: differential analyses can be stratified by sex or fitted as group-by-sex interaction models, feature selection and classifiers are trained per sex, and the multi-omics biomarker discovery engine reports whether the selected panel differs between female and male patients. Methodological safeguards that are rarely exposed in graphical tools are built in, including a batch-by-phenotype confounding block, an optional sealed validation hold-out reserved before any analysis runs, a held-out split taken before feature selection, a leakage-safe nested cross-validation tab, and a study-wise random-effects meta-analysis. Genetic evidence is integrated through Mendelian randomisation and colocalisation for both expression and methylation, and a cross-omics evidence classifier combines expression, methylation and QTL support into a single tier per gene. An embedded assistant, ArthOChat, answers questions about the methodology and the user\'s live results with deterministic sampling and a grounding check that flags unsupported references. The application is delivered with pinned dependencies (renv), a Dockerfile, provenance manifests and a test suite of 105 files (3,552 passing assertions, 0 failures) run in continuous integration. Applied to the bundled whole-blood RA cohort, ArthOMix identified **\[N\]** sex-specific candidate genes and a **\[N\]**-gene cross-tissue-validated panel. ArthOMix is available at <https://arthomix-differential-methylation-multiomics.serveousercontent.com/> and <https://github.com/shweta-rai11/ArthOMix-app> under the MIT licence.

**1. Introduction**

**1.1 Interactive web tools in omics research**

High-throughput omics experiments measure thousands to millions of molecular features per sample. Transcriptomic arrays and RNA sequencing quantify the expression of tens of thousands of genes, while methylation arrays interrogate hundreds of thousands of CpG sites (Shabalin et al., 2018; Yamada et al., 2020). At this dimensionality, analysis and interpretation depend on visualisation: researchers rely on graphical summaries to find structure, compare groups, and form hypotheses (Nusrat et al., 2019; Mougin et al., 2018). Interactive visualisation extends this further by letting the user filter features, inspect individual samples, and change parameters without re-running a script (Chishtie et al., 2022). For this reason, an increasing share of bioinformatics methods are now delivered as browser-based web applications that expose a statistical workflow to users without programming expertise (Saia et al., 2022; Mani et al., 2025). A web application separates a front end (the user interface), a back end (the code that processes the data) and, where needed, a database (Dittrich et al., 2023). Tools such as GREIN, the GEO RNA-seq Experiments Interactive Navigator, show the value of this model by letting users re-analyse public GEO data to their own specification (Mahi et al., 2019), and web front ends also allow researchers to publish their analyses to a broader audience in reproducible form (Balzer et al., 2020).

**1.2 R Shiny for bioinformatics applications**

Shiny is an R package and framework for building interactive web applications directly from R code (Chang et al., 2024). Its relevance to bioinformatics comes from its position inside the R ecosystem: differential expression, methylation analysis, enrichment, network analysis and multi-omics integration are all implemented as R or Bioconductor packages, so a Shiny application can wrap those methods without re-implementing them (Giorgi et al., 2022; Jia et al., 2022; Dyce et al., 2025). Three features of Shiny are central to how ArthOMix is built.

First, a Shiny application is divided into a user interface, which declares inputs (file uploads, sliders, selectors) and output placeholders (plots, tables, text), and a server function, which holds the computational logic and receives the current input values, writes outputs, and has access to the session (Jia et al., 2022). Second, Shiny is reactive: rather than executing sequentially, the server re-evaluates only the computations whose inputs have changed, using reactive expressions for cached intermediate values and observers for side effects such as writing files or updating other inputs (Wojciechowski et al., 2015). Render functions such as renderPlot() and renderTable() bind these computations to the interface, so an output refreshes automatically when its dependencies change. Third, Shiny modules encapsulate a paired UI function and server function under a namespace, which allows a large application to be decomposed into independent, testable units (Brun et al., 2025). This modular pattern is essential for an application with many analytical stages, and it is complemented by extension packages that add layouts and widgets (Reiter et al., 2021; Kasprzak et al., 2020). Published examples such as ShinyDSP (Kim et al., 2025) and FastqCleaner (Roser et al., 2019) show Bioconductor methods and interactive visualisation combined in a single Shiny platform.

Python offers comparable frameworks, including Streamlit and Dash for interactive dashboards and Flask or FastAPI for general web services (Tewari, 2025). For an application whose analytical core is statistical genomics, the deciding factor is direct access to Bioconductor, which only R provides. Shiny\'s known limitations, namely heavy dependency stacks that complicate deployment and memory pressure from large datasets and long computations (Jia et al., 2022), are addressed in ArthOMix through asynchronous execution, upload caps, sandboxed file parsing and containerised deployment (Section 2.2).

**1.3 Existing Shiny applications for omics analysis**

More than 470 biological web applications have been built with Shiny (Jia et al., 2022). Early tools targeted single tasks: shinyMethyl provided interactive quality control for Illumina 450K arrays (Fortin, Fertig & Hansen, 2014), shinyGEO analysed GEO datasets for differential expression and survival (Dumas et al., 2016), START offered interactive RNA-seq exploration (Nelson et al., 2017), and iDEP combined 63 Bioconductor packages into a guided workflow from quality control to pathway analysis (Ge et al., 2018). Later tools widened coverage: DEBrowser let the user choose among differential-expression engines (Kucukural et al., 2019), iSEE provided panel-based exploration of Bioconductor objects with code export (Rue-Albrecht et al., 2018), and ShinyGO performed functional enrichment on externally generated gene lists (Ge et al., 2020).

Recent applications have moved toward multi-omics and single-cell data. Cerebro (Hillje et al., 2020) and ShinyCell (Ouyang et al., 2021) explore processed single-cell datasets, Quickomics (Gao et al., 2021) and Omics Playground (Akhmedov et al., 2019) interpret pre-computed transcriptomic and proteomic results, Holomics (Munk et al., 2024) extends Shiny to multi-omics integration, xOmicsShiny (Gao et al., 2025) offers cross-omics analysis and pathway mapping across transcriptomics, proteomics, metabolomics and lipidomics, OmNI (Potter et al., 2026) provides a modular framework for interactive multi-omics integration, and Omics BioAnalytics (Dyce et al., 2025) focuses on multimodal biomarker-panel discovery and assessment.

Methylomics has followed a narrower path. shinyÉPICo (Morante-Palacios & Ballestar, 2021) carries user-supplied IDAT files through normalisation, differentially methylated position and region calling for 450K and EPIC arrays, but remains a single-omics tool with no downstream functional or genetic interpretation. The SMART App (Li et al., 2019) links TCGA methylation to expression and survival, and ShinyTHOR (Navarrete-Bencomo et al., 2025) spans transcriptomic, metabolomic, methylomic, proteomic and miRNA layers, but both operate over public repositories and do not accept user data.

Table 1 summarises this landscape. Two observations motivate ArthOMix. First, no reviewed tool treats sex as an analytical variable: none stratifies by sex or fits interaction models, and none reports sex-specific panels. Second, the tools closest in scope, Omics BioAnalytics, Holomics, xOmicsShiny and OmNI, integrate omics layers but do not connect them to genetic evidence (Mendelian randomisation, colocalisation), do not offer a methylomics pipeline from raw IDAT to validated classifier, and do not combine same-sample multi-omics integration with result-level cross-omics comparison in one application.

**1.4 Sex differences in rheumatoid arthritis and in omics data**

The bundled reference data in ArthOMix, and the case study reported in Section 3, concern rheumatoid arthritis. RA is a chronic autoimmune disease affecting about 0.5 to 1 % of adults, and it is roughly three times more common in women than in men (Smolen, Aletaha & McInnes, 2016). Sex differences extend beyond prevalence: women and men differ in innate and adaptive immune responses, in autoantibody profiles and in response to therapy (Klein & Flanagan, 2016). At the molecular level, a substantial fraction of X-linked genes escape X-chromosome inactivation, many of them immune regulators, producing sex-biased expression across tissues (Tukiainen et al., 2017), and thousands of autosomal CpG sites are differentially methylated between men and women (Singmann et al., 2015). Pooling sexes therefore risks two errors: a signal present in one sex is diluted, and a sex-associated feature is mistaken for a disease-associated one when case--control ratios differ by sex. **\[AUTHOR: add one or two RA-specific citations reporting sex-differential gene expression or methylation if available.\]** ArthOMix is designed so that every differential, feature-selection and classification step can be run per sex, or as an explicit interaction model, rather than adjusting sex away as a covariate.

**1.5 Cross-omics versus multi-omics**

ArthOMix distinguishes two ways of combining transcriptomic and methylomic evidence, because they answer different questions and need different data. *Cross-omics* integration works at the level of results: it takes a differential-expression table and a differential-methylation table, which may come from different cohorts, and asks whether the same genes change in both, and in which direction. It needs no paired samples. *Multi-omics* integration works at the level of samples: it takes matched expression and methylation matrices measured on the same individuals and models them jointly, so that latent factors, sample clusters and candidate feature panels reflect coordinated variation across layers (Argelaguet et al., 2018; Singh et al., 2019). Cross-omics is available to any user with two result tables; multi-omics requires a matched cohort. Both are implemented, as separate verticals, and the interpretation layer records which kind of evidence supports each candidate.

**1.6 Gap, aim and objectives**

From the literature reviewed above, methylomics is positioned either as an isolated single-omics pipeline or as a pathway-exploration layer over public repositories, and no Shiny application treats sex as a primary analytical variable across transcriptomics, methylomics and their integration. This gap led to the development of ArthOMix. Its aim is to provide a single, modular, reproducible interface in which a researcher can take user-supplied, GEO-retrieved or bundled data from raw input to an interpreted, sex-aware biomarker panel. The specific objectives were to:

1.  implement complete transcriptomics and methylomics pipelines (quality control, normalisation, differential analysis, network analysis, genetics, feature selection, classification, validation, interpretation) as independent Shiny sub-modules;

2.  support three isolated data-intake paths per vertical (upload, GEO fetch, bundled reference) so that state from one dataset cannot contaminate another;

3.  expose sex-stratified and sex-interaction analyses at every stage where a group comparison is made;

4.  integrate genetic evidence (Mendelian randomisation, colocalisation) for both expression and methylation, and combine expression, methylation and genetic support into a single evidence tier per gene;

5.  implement both result-level cross-omics comparison and sample-level multi-omics integration, and

6.  embed an assistant that explains the methodology and summarises the user\'s live results without fabricating references.

**2. Methods**

**2.1 System design and architecture**

ArthOMix is written in R using the Shiny framework and follows the module pattern: each analytical unit is a triple of a configuration entry, a UI function and a server function, registered in a central module index and loaded by a small set of loader scripts. The application has four modules (verticals) and 45 sub-modules: Transcriptomics (17), Methylomics (15), Cross-Omics (4) and Multi-Omics (9). Table 2 lists them. **\[AUTHOR: insert Figure 1, system architecture (UI shell, module index, shared reactive state, ArthOChat, data sources); Figure 2, module map; Figure 3, data-flow arrows between sub-modules.\]**

Each vertical holds its data and results in shared reactive containers (dataset and results objects for transcriptomics, methylomics, cross-omics and multi-omics). Downstream sub-modules read from these containers rather than from each other, so a sub-module can be run alone or as part of a chain, and a Dataset sub-module in each vertical is the single entry point through which data are loaded. The Dataset sub-modules record the source of the active data (upload, GEO, or bundled reference) and downstream sub-modules use this to adapt behaviour, for example by hiding cohort-merging tabs that only apply to the bundled cohort, or by short-circuiting to precomputed results for the reference data. Loading a new dataset replaces the previous one and resets dependent results. The interface is a sidebar shell with a per-vertical pipeline summary, a light/dark theme toggle, a header button that opens the session\'s analysis records (Section 2.2), and a slide-out drawer for the ArthOChat assistant.

**2.2 Software engineering and reproducibility**

The application runs on R 4.4.2. Dependencies are declared in a DESCRIPTION file (about 95 imports and six GitHub remotes) and pinned in an renv.lock file of about 96 packages, and a Dockerfile builds the complete environment. **\[AUTHOR: insert Table 3, R/Bioconductor packages by sub-module, generated from DESCRIPTION.\]** Long-running computations execute asynchronously through the future and promises packages on <span style="color:purple">a pool of pre-warmed worker processes sized from the host's available CPU cores (minimum two, capped at six, overridable via an environment variable for a given deployment)</span>, so the interface stays responsive during model fitting. Uploads are capped at 3 GB, and RDS files are parsed in an isolated callr subprocess with a 1 GB memory cap so that a malformed or malicious object cannot take down the session. In the transcriptomics vertical every analysis run button (normalisation adoption, preprocessing and batch correction, differential expression, WGCNA, candidate genes, Mendelian randomisation, colocalisation, feature selection, the diagnostic model and its external validation, sex interaction, cross-tissue and cross-ancestry replication, enrichment, deconvolution, nomogram and Biomarker Card) pushes a provenance record, holding the parameters, seed, R and package versions and a checksum of the input data, to a session-wide \"Analysis records\" panel in the application header, from which all records of a session can be exported as one JSON file; Differential Expression additionally offers a per-run manifest download. In the methylomics vertical only the differential-methylation (DMP) run writes such a manifest; the multi-omics vertical writes a record from every sub-module (Section 2.7); <span style="color:purple">the cross-omics vertical is now also wired to the session log, across all three of its sub-modules (Section 4.3)</span>. User uploads are held in session memory only and are not persisted to disk.

Correctness is enforced by a testthat suite of 105 test files plus two helpers (grown from 93 earlier in this drafting process, 2026-09-08), covering module servers, helper functions and the shared data contracts. At the time of writing the suite reports 3,552 passing assertions, 0 failures, 0 errors and 12 skips when run with 8 parallel processes (full results in Section 3.5), and it runs on every push through GitHub Actions. A separate verification protocol for the assistant (Section 2.8) is kept under tests/arthochat_verification/.

**2.4 Transcriptomics module**

**2.4.1 Dataset**

The Dataset sub-module is the only entry point for transcriptomic data and holds one active dataset at a time. Three intake paths are provided. *Upload* accepts an expression matrix and a metadata table as CSV or RDS (tab-delimited text is also parsed). The metadata table has one row per sample and must contain a sample identifier and a group column; sex and batch columns are optional and can be mapped from any column name. The expression matrix has genes as rows and samples as columns; a CSV must have gene identifiers in the first column and numeric values elsewhere, and an RDS is expected to contain a numeric matrix with gene and sample names, though only the object\'s class is checked on load, not its numeric content or its row/column names. The user declares whether the values are raw counts, normalised or log2-transformed, and the declaration is validated against the distribution of the matrix, so that raw counts declared as log2 data are rejected. At least four sample identifiers must match between the two files; duplicate sample identifiers block the upload outright, while duplicate gene identifiers are only reported, since downstream steps keep just their first occurrence. *GEO fetch* retrieves a series by accession through GEOquery (Davis & Meltzer, 2007), lets the user choose among platforms when a series has more than one, collapses probes to gene symbols using the platform annotation, and warns when fewer than 15 samples are available because downstream network analysis becomes unreliable. *Preloaded Datasets* is a five-option picker: the default entry is the bundled, sex-stratified whole-blood RA cohort (Table 4; GSE93272 + GSE110169, merged and batch-corrected), and four individual cohorts can also be selected directly --- the same two whole-blood series, the GSE15573 PBMC validation cohort, and a GSE89408 synovial-tissue validation cohort, which is not whole blood. Regardless of path, the source type is recorded with the dataset and read by every downstream sub-module.

A fourth control on the same tab, *Reserve validation samples*, takes a stratified fraction of the loaded samples (default 30 %, stratified by group and, when present, sex, with a fixed seed) out of the active dataset before any analysis runs. From that moment every downstream sub-module, including differential expression, WGCNA, candidate gene identification, feature selection and model training, sees only the discovery samples; the reserved samples are held as a sealed set that only the Diagnostic Model\'s External Validation tab can read (Section 2.4.10), where they are scored with the frozen models. Reserving disables the precomputed bundled-reference shortcuts, because those were computed on all samples, so every step then runs live on the discovery subset. If a later step replaces the active matrix with one that again contains reserved samples (Preprocessing rebuilding the bundled cohort from raw files, or Overview adopting a normalised matrix), the reserved samples are sealed away again automatically and the status records that they passed through that processing step; this is a normalisation-stage exposure only, and no selection, network or model step ever sees them. Releasing the reservation restores the full dataset and clears results computed on the discovery subset. Each reservation writes a provenance record with the seed, fraction and the identifiers on both sides of the split.

The bundled matrix is the 183-sample training partition of the whole-blood case study *after* quantile normalisation and ComBat. The sealed 30 % internal hold-out, the frozen normalisation and batch parameters that were projected onto it, and the repeated nested cross-validation described in Section 3.1 are products of the archived analysis scripts and are not shipped with the application; the external blood cohort GSE15573 *is* shipped, as raw probe data that the Diagnostic Model\'s External Validation tab collapses to gene symbols and log2-transforms on first use, and it is used there only to score frozen models (Section 2.4.10). The application therefore implements a generalised, live version of the pipeline that any cohort can pass through. It does not reproduce the internal hold-out and nested cross-validation figures of Section 3.1 from the bundled matrix alone, so those figures are reported together with the application\'s own re-run on the bundled cohort (its nested cross-validation AUC and its GSE15573 external AUC) so that the archived and live estimates can be compared.

**2.4.2 Overview and Datasets**

This sub-module presents the active dataset through four tabs. The **Datasets** tab lists the GEO accession, role and provenance of each cohort in the active dataset and is shown for every intake path, since the bundled cohort also has accessions. The **Metadata** and **Expression** tabs render the sample table and the expression matrix, with an independent \"dataset to inspect\" selector so that the individual cohorts of a merged reference can be examined separately. The **QC** tab has four sub-tabs.

*Missing values* audits every metadata field and counts true NA values together with four placeholder strings, exactly \"\", \"NA\", \"N/A\" and \"unknown\" (case-sensitive), since incomplete covariates bias downstream models (Kwak & Kim, 2017). Results are a sorted bar chart of complete versus missing entries per field and a summary table with counts and percentages.

*Outliers* computes three per-sample metrics, total signal, number of detected features and mean correlation with the other samples, and flags a sample when signal or feature count is unusually far from the cohort median, or when its correlation is unusually low (low side only). Distance is measured in units of the median absolute deviation (MAD), chosen because it is robust to the outliers it is meant to detect, unlike the standard deviation (Rindskopf & Shiyko, 2010). The threshold is a slider from 2 to 6 MAD (default 3). Flagged samples are listed and plotted; nothing is removed automatically, and the full per-sample table can be downloaded, so that the user can decide before differential expression or classification, where outliers distort results (Kircher et al., 2023).

*Normalised data* tests whether samples are on a comparable scale. A dataset is flagged as needing normalisation if its maximum value exceeds 100, if the standard deviation of per-sample medians exceeds 0.5, or if the standard deviation of per-sample interquartile ranges exceeds 0.5. The tab shows per-sample distributions, a scree plot, and a PCA scatter plot that can be coloured by any metadata column, with optional 68 % normal confidence ellipses for groups of at least four samples and optional sample labels (Ringnér, 2008). If normalisation is indicated, quantile normalisation (Bolstad et al., 2003; Zhao, Wong & Goh, 2020) can be applied in place, with a before-and-after comparison, and the normalised matrix can be adopted as the active dataset for all downstream sub-modules. The bundled reference remains read-only.

*Group* is a filter builder: categorical columns with 2 to 30 levels become pickers and numeric columns become range sliders, composition charts update live, and the filtered metadata can be downloaded.

**2.4.3 Preprocessing and batch correction**

This sub-module has five tabs: Preprocessing, Merge Datasets, Batch Correction, Study-wise Meta-analysis, and Data Exploration. Merge, Batch Correction and Data Exploration apply to the bundled multi-cohort reference only and are hidden for uploaded or GEO data, which arrive as a single cohort.

**Preprocessing** selects which reference cohorts to prepare, separately or together, and applies one of three log2 policies. *Auto-detect per cohort* uses the quantile heuristic popularised by GEO2R (Barrett et al., 2013): the 99th percentile of strictly positive values is compared with 100, and a cohort above that threshold is treated as linear-scale and log2-transformed, while a cohort at or below it is left unchanged. Because the check is per cohort, two cohorts prepared together may be treated differently. *Force log2* transforms unconditionally. *Skip* leaves values untouched, which is required for raw RNA-seq counts that must stay non-negative for count-based normalisation. Whenever log2 is applied, zero or negative values become missing (log2 is undefined there) and any gene with a missing value in any sample is dropped, so Force log2 on already-logged data can reduce the gene count. Remaining missing values are imputed per gene with the gene\'s median.

**Merge Datasets** intersects cohorts on shared genes (a single cohort may also be passed through), collapses probes to genes by median, maximum mean or mean, and reports a Venn diagram, a region table and downloads.

**Batch Correction** first normalises the merged matrix (Auto-detect, Already normalised, Quantile, or trimmed mean of M-values, TMM, for raw counts; Robinson & Oshlack, 2010), then corrects for a batch variable chosen from the metadata. Correction methods are ComBat (Johnson, Li & Rabinovic, 2007; parametric or non-parametric, mean-only, optional reference batch), limma removeBatchEffect (Ritchie et al., 2015), and surrogate variable analysis with the number of surrogate variables estimated automatically (Leek et al., 2012). ComBat-seq for raw counts (Zhang, Parmigiani & Johnson, 2020) is reached by selecting TMM and correcting before normalisation. Biological columns can be protected so that group differences are not removed with the batch effect (Yu et al., 2024). Two safeguards are enforced: every batch level must contain at least two samples, and a batch-by-phenotype confounding test blocks the run when batch and group are confounded, requiring an explicit override (the block does not apply to surrogate variable analysis, which does not use a batch label). A checkbox skips correction when the batch column has a single level. PCA before and after correction is displayed together with an ANOVA of the first principal component on batch, and the corrected matrix can be adopted as the active dataset.

**Study-wise Meta-analysis** offers an alternative to merging. Each cohort is analysed separately with limma, or limma-voom for counts (Law et al., 2014), and per-gene effects are combined by DerSimonian--Laird random-effects meta-analysis (DerSimonian & Laird, 1986), reporting τ², Cochran\'s Q, I² and Benjamini--Hochberg adjusted p-values, with a volcano plot coloured by heterogeneity.

**Data Exploration** is a self-contained exploratory tool for a user-uploaded matrix, decoupled from the active dataset. It reports overview statistics, descriptive statistics, distributions, normality, a normalisation-status verdict, outliers, PCA, a correlation heatmap, missingness, low-variance features, the mean--variance relationship, log2 before-and-after plots and a plain-language summary.

**2.4.4 Differential expression**

The Differential Expression sub-module fits either limma (Ritchie et al., 2015; default) or DESeq2 (Love, Huber & Anders, 2014), chosen by the user; a data-scale check blocks an invalid combination, such as DESeq2 on log-scale data. For uploaded data, the input is cleaned before modelling: probe identifiers are mapped to gene symbols when an annotation file is supplied, duplicate features are collapsed to their mean, sample identifiers are matched between expression and metadata, and zero-variance and empty features are removed. The bundled reference is collapsed earlier in its pipeline using the WGCNA collapseRows function with the MaxMean rule.

The contrast can be made on any metadata column with 2 to 20 distinct values, not only a fixed group column, and a second column can be used either to filter the samples to one level or to adjust for it as a covariate. At least six samples and three per level are required. Results comprise a volcano plot, a z-scored heatmap of the top significant genes, a ranked table (log2 fold change, p-value, adjusted p-value, direction) and CSV and PNG downloads, all filtered by user-adjustable thresholds (defaults adjusted p \< 0.05, \|log2 fold change\| \> 0.5). Because a post-hoc fold-change gate tests against log2FC = 0 and then discards small effects, the sub-module also offers limma\'s treat, which places the cutoff inside the null hypothesis (McCarthy & Smyth, 2009), and the result panel always reports the significant-gene count at \|log2 fold change\| \> 0.1, 0.5 and 1.0 so that the sensitivity of the count to this choice is visible (on the bundled cohort a 0.1 gate, a 1.07-fold change, calls roughly half the transcriptome significant). The last eight runs are retained in the session and each run writes a provenance manifest to the session-wide analysis record.

Sex-specific analysis is a first-class use: with sex as the filter, the disease-versus-control contrast is run independently within the female and male subsets, producing female and male DEG lists. These lists are consumed by Candidate Gene Identification, the Biomarker Card, Cross-Tissue Validation and the Cross-Omics vertical. The WGCNA sub-module does not read DEG lists; it uses the expression matrix directly.

**2.4.5 WGCNA**

Weighted gene co-expression network analysis (Langfelder & Horvath, 2008; Zhang & Horvath, 2005) is organised in six tabs.

**Filter and QC** intersects sample identifiers between metadata and expression, removes genes with missing values, requires at least 15 samples, and applies an optional regular-expression exclusion (for example to drop control probes). Seven gene-selection modes are offered: all genes (default for the reference cohort); the top N genes by median expression (default 5,000; range 200 to 20,000); the top N by variance (default 2,000; range 200 to 10,000); a variance-percentile cutoff or a MAD-percentile cutoff (50 to 99 %, default 75 %), which retain any gene at or above the percentile so that the count scales with the data (Nguyen & Zeng, 2025); a mean-expression cutoff (default 0, step 0.5); and a custom panel of pasted gene symbols, trimmed, de-duplicated and intersected with the matrix. A minimum of 20 genes (custom panel) or 50 (other modes) is enforced.

**Soft Power** sets the network type (signed, unsigned, signed hybrid; Dai et al., 2019), the correlation (Pearson or biweight midcorrelation; Song, Langfelder & Horvath, 2012) and a target scale-free fit R², and evaluates candidate powers with pickSoftThreshold. Power selection defaults to manual (12 for the reference cohort, 7 for uploads) and the tab verifies scale-free topology empirically at the chosen power. Diagnostic plots are scale-free fit, mean connectivity and exponential fit against power, and a topology-check plot with fit statistics, the last downloadable as PNG.

**Modules** builds the topological overlap matrix (TOM; Yip & Horvath, 2007; signed, unsigned or signed Nowick), clusters genes hierarchically and cuts the dendrogram with dynamic tree cutting. Parameters are minimum module size (30 for the reference cohort, 66 for uploads), deep split (0 coarse to 4 fine) and merge cut height (0.25 reference, 0.30 uploads). Outputs are a dendrogram with module colours, a module-size chart and an eigengene-network heatmap, downloadable as CSV or RDS. Results are cached to disk, and the reference cohort short-circuits to precomputed modules. One network is built on all samples of the active dataset; sex enters the analysis only as a trait in the Module--Trait step. The application does not build separate female and male networks or compute module preservation between them; the sex-stratified networks and the modulePreservation statistics of the case study belong to the archived analysis scripts (Section 2.4.1).

**Module--Trait** accepts any metadata column with at least two values as a trait. Categorical traits are expanded to one binary indicator per level so that direction is interpretable (for example \"up in RA\" versus \"up in control\"), and levels can be dropped, which sets those samples to missing for that column only. Numeric traits pass through unchanged. Each module eigengene is correlated with each trait column (Pearson or bicor, following the Soft Power choice) and the heatmap shows r with the p-value computed from the non-missing samples for that column (p-values are printed for uploaded data). Modules with \|r\| ≥ 0.5 and p \< 10⁻⁸ against the disease trait are labelled disease modules and feed Candidate Gene Identification.

**Hub Genes** computes, for a chosen module and trait, module membership (kME, the correlation of each gene with the module eigengene) and gene significance (GS, its correlation with the trait), and reports genes passing both thresholds (defaults \|kME\| ≥ 0.8, \|GS\| ≥ 0.2; Fuller et al., 2007), with a kME-versus-GS scatter plot, a Cytoscape edge export and a STRING link.

**Enrichment** tests over-representation of Gene Ontology Biological Process terms and KEGG pathways in hub genes or in whole modules using clusterProfiler (Yu et al., 2012), with Benjamini--Hochberg correction (Benjamini & Hochberg, 1995). The background is the set of genes used to build the network, not the whole genome, to avoid bias toward the filtered subset. Terms are ranked by adjusted p-value and filtered by a q-value cutoff; the CSV export contains the unfiltered table.

**2.4.6 Candidate gene identification**

This sub-module intersects the WGCNA disease-module gene set (the grey unassigned module is excluded) with the female and male DEG lists, so that a gene must have both network and differential-expression support (Sun et al., 2024). Because the module background is shared and the DEG lists are sex-specific, any difference between the female and male candidate sets reflects sex-specific differential expression. If the dataset has no sex column, a pooled analysis is used. An optional pasted gene panel narrows the search to a biological process (hidden for the bundled dataset, whose panel is fixed), and an optional causal-evidence refinement retains only genes with Mendelian-randomisation p \< 0.05 and colocalisation PP.H4 ≥ 0.8 from the genetics sub-modules. Outputs are sex-specific Venn diagrams, candidate tables (gene symbol, log2 fold change, adjusted p-value, module name, mean expression), a single hypergeometric enrichment p-value for the overlap, CSV and PNG downloads, and a combined set that can be Female only, Male only, Union (default) or Intersection.

**2.4.7 Mendelian randomisation**

Mendelian randomisation (MR) uses genetic variants as instruments to estimate the causal effect of gene expression on disease risk (Richmond & Davey Smith, 2022). The sub-module runs a two-sample design (Minelli et al., 2021) in three tabs: **MR overall** for interactive analysis, and **MR female** and **MR male** for the sex-stratified results of the bundled cohort. In bundled mode the exposure is a cis-eQTL instrument set from eQTLGen (Võsa et al., 2021), harmonised against the Okada et al. (2014) RA GWAS obtained through OpenGWAS (ieu-a-832) with TwoSampleMR (Hemani et al., 2018); in upload mode the user supplies exposure or outcome summary statistics and the sub-module formats and harmonises them. Instruments are filtered by eQTL p-value (default 5 × 10⁻⁸) and F-statistic (default F \> 10). MHC exclusion is available for bundled data and LD clumping for uploaded data. Estimators are the Wald ratio, inverse-variance weighting (Burgess, Butterworth & Thompson, 2013), weighted median (Bowden et al., 2016), MR-Egger (Bowden, Davey Smith & Burgess, 2015) and, with at least four instruments, MR-PRESSO (Verbanck et al., 2018), chosen by instrument count, with Cochran\'s Q, the Egger intercept and a selectable confidence level. Each gene receives a verdict of ROBUST, MHC-DEPENDENT or UNTESTABLE. Scatter, funnel and leave-one-out plots, an FDR-corrected batch screen across all genes, and XLSX tables are provided.

**2.4.8 Colocalisation**

Colocalisation tests whether a cis-eQTL signal and a disease-risk signal at a candidate gene share a single causal variant, using coloc (Giambartolomei et al., 2014; Reales et al., 2026). The eQTL side is a bundled cis-window instrument covering the candidate panel; the disease side defaults to the bundled RA GWAS (Okada et al., 2014) and can be replaced by an uploaded GWAS, harmonised to the instrument with harmonise_data() from TwoSampleMR. At least ten shared SNPs are required. The case fraction (default 0.33) calibrates the disease-trait Bayes factors, a quantitative-trait mode is available, and the priors p1, p2 and p12 are adjustable with a validator enforcing p12 ≤ min(p1, p2) (Pullin & Wallace, 2025). The sub-module reports posterior probabilities for the five hypotheses H0 to H4, with PP.H4 interpreted against 0.8 (strong) and 0.5 (suggestive) bands, per-SNP PP.H4, a regional association plot and a downloadable per-SNP table.

**2.4.9 Feature selection**

Feature Selection reduces a candidate gene panel to a compact biomarker panel and is run separately for Female, Male and Pooled samples. Before any selection, a seeded held-out split (default 30 %) is taken and the held-out sample identifiers are passed to the Diagnostic Model, so that the test set is never seen by the three selectors. The candidate genes entering this step were, however, chosen by differential expression and WGCNA on all samples, including the future test samples, so the split protects the selection step only; the Diagnostic Model\'s nested cross-validation (Section 2.4.10) is the estimate that accounts for the upstream choice. When validation samples were reserved on the Dataset tab (Section 2.4.1), those samples were never part of this pool either, and scoring them in the External Validation tab is the estimate that is leakage-safe for the whole discovery pipeline. On the training portion, three algorithms are applied: LASSO logistic regression with λ chosen by cv.glmnet (Friedman, Hastie & Tibshirani, 2010; Tibshirani, 1996), random-forest mean-decrease-in-Gini importance, retaining genes whose importance exceeds the mean across candidates, with mtry tuned through caret (Breiman, 2001; Kuhn, 2008), and SVM recursive feature elimination with the cost tuned through e1071::tune (Guyon et al., 2002; Sanz et al., 2018). Class weighting is available for imbalanced groups, the panel is capped at the 200 most variable genes, and an MHC-exclusion sensitivity run is offered. The four tabs, LASSO, Random Forest, SVM-RFE and Overlap, each show a diagnostic plot, the selected genes and a downloadable table; the overlap rule (genes selected by all three, or by any two) is configurable. Users may run the bundled cohort, which has a precomputed fast path, or upload their own matrix, metadata and gene list, which pass through the same filters and parameters.

**2.4.10 Diagnostic model**

The Diagnostic Model trains and evaluates classifiers that separate two user-chosen groups on a gene panel taken from Feature Selection, a pasted list or a WGCNA module. Models are fitted separately for Female, Male and Pooled cohorts. The user sets the reference and comparison group, a train/test ratio (overridden by the held-out identifiers from Feature Selection when available) and a class-weighting scheme. Four classifiers are fitted on the training set with cross-validated tuning: unpenalised logistic regression, elastic net, random forest and support vector machine (Alam et al., 2025). Training-set and cross-validated AUC are reported, and the fitted models are scored on the held-out test set with AUC and DeLong confidence intervals (DeLong, DeLong & Clarke-Pearson, 1988; Robin et al., 2011), precision--recall AUC, F1, Matthews correlation coefficient, the Youden threshold, calibration (Brier score, slope and intercept) and a DeLong test of training versus test AUC. For each gene in the panel, a per-gene AUC and an unpaired Wilcoxon rank-sum test between groups are computed, and genes meeting an adjustable hub rule (default AUC ≥ 0.85 and p \< 0.05) are flagged (Çorbacıoğlu & Aksel, 2023).

Two validation tabs address generalisation. The **Leakage-safe Validation** tab runs a nested cross-validation in which limma ranking and LASSO selection are repeated inside every outer fold, so that no test sample contributes to feature choice. Because the candidate genes are always chosen on the full sample pool upstream (Section 2.4.9), this nested estimate is the headline metric for every run; the split estimate is reported beside it and labelled as protected against feature-selection leakage only, and for the bundled panel, which was selected without any hold-out, as exploratory. Strata with fewer than 20 samples in the smaller group are labelled exploratory, with the number of events per candidate variable shown (Peduzzi et al., 1996; Riley et al., 2019), and fewer than 10 per group are refused. The **External Validation** tab is the only true external validation of a trained model in the transcriptomics vertical. It scores the models fitted in Model Training, unchanged and without re-tuning, on an independent cohort: the sealed validation samples reserved on the Dataset tab (Section 2.4.1), which no discovery step has seen and which therefore give the only estimate that is leakage-safe for the whole pipeline; the bundled external blood cohort GSE15573 (PBMC, 18 RA and 15 controls, both sexes; collapsed to gene symbols and log2-transformed on load); or a user-uploaded expression matrix and metadata. A Female or Male panel is by default scored on the matching sex of the external cohort. External samples are z-scored within the external cohort and the training Youden threshold is reused, so the AUC is the primary external metric and sensitivity and specificity are reported as threshold-dependent. Per-gene discrimination of the same panel is shown alongside. The frozen-model result is written to the shared session results for the panel\'s stratum, where the Biomarker Card reads it (Section 2.4.17), and every run pushes a provenance record. The external cohort is never used for fitting. Performance tables and fitted model bundles (RDS) are downloadable.

**2.4.11 Sex interaction analysis**

Where the sex-stratified DEG lists ask \"which genes change within each sex\", this sub-module asks \"does the disease effect differ between sexes\". It fits a limma model of the form group × sex, with optional additional covariates, on the active dataset, and extracts four coefficients from the single fit: the interaction term, the disease effect within the reference sex, the disease effect within the comparison sex, and the sex main effect. The user chooses reference and comparison groups and sexes and an adjusted p-value threshold (default 0.05). The design matrix is checked for full rank, per-cell sample counts are displayed, and a warning with the minimum detectable effect is shown when any cell has fewer than ten samples. Output is a per-gene table with counts of genes tested and significant, downloadable as CSV. A gene can be significant here without being differentially expressed in either sex alone, and vice versa, which is why both views are provided.

**2.4.12 Cross-tissue replication**

This sub-module asks whether the gene-level signal of a panel discovered in blood replicates in synovial tissue, using the bundled synovium RNA-seq cohort (GSE89408; Guo et al., 2017) or a user-supplied tissue cohort. A tissue-provenance gate refuses to compare a panel against a cohort of the same tissue. Four tabs, each with Pooled, Female and Male sub-tabs, guide the user from gene to panel to comparison. **Synovium Discovery and Concordance** reports, for each panel gene, the tissue fold change (limma-voom), adjusted p-value, per-gene synovium AUC, and whether the direction agrees with blood; a gene is flagged as replicated across tissues when it is concordant, significant and reaches AUC ≥ 0.70 (a per-gene screening rule with no correction for the number of panel genes). **Panel Classifier -- Full Fit** refits logistic regression, elastic net, random forest and SVM on the tissue cohort and reports their performance. **Panel Classifier -- Cross-Validated** repeats the four models across cross-validation folds and pools the held-out predictions, correcting the optimism of the full fit. **Cross-Dataset Comparison** sets the tissue performance beside the original blood performance. The comparison is a refit of the panel in tissue, not a transfer of the blood-trained model, which is the appropriate test when platforms differ (microarray versus RNA-seq); it is therefore a replication of the gene signal and not an external validation of the diagnostic classifier, which is available only through the Diagnostic Model\'s External Validation tab.

**2.4.13 Cross-ancestral MR replication**

Cross-ancestral MR replication asks whether the genetic support for a gene replicates across populations. It operates on the bundled cohort\'s genetically prioritised gene lists and is independent of whichever expression dataset is loaded; it neither reads nor validates the diagnostic model, and the interface says so whenever a non-bundled dataset is active. It is a Mendelian-randomisation analysis with three GWAS arms rather than three expression datasets: the discovery arm is the Okada et al. (2014) European-ancestry RA GWAS, the replication arm is the Stahl et al. (2010) European GWAS, and the transfer arm is the BioBank Japan East Asian RA GWAS (Ishigaki et al., 2022), all instrumented with the project\'s cis-eQTL instruments. A gene passes when its causal estimate is significant in the discovery arm, replicates in the second European arm and transfers to the East Asian arm at the user-chosen threshold. A gene that cannot be tested in an arm because its instruments are absent from that GWAS is labelled \"untestable\" rather than \"failed\", because absence of data is not evidence of absence. The Female and Male tabs report the sex-specific candidate genes. Users can replace any arm with an uploaded per-SNP GWAS, which is run live through TwoSampleMR against the same instruments; the required format is given in the supplementary file. **\[AUTHOR: make sure the supplementary file exists and is referenced by name.\]** Outputs are a validated-gene count, a comparison plot across arms, a significance-ranking plot and a downloadable table.

**2.4.14 Functional enrichment**

Functional Enrichment runs over-representation analysis of a user\'s gene list against Gene Ontology Biological Process, KEGG and Reactome using clusterProfiler and ReactomePA (Yu et al., 2012; Yu & He, 2016), mapping symbols to Entrez identifiers through org.Hs.eg.db and using the genes measured in the loaded dataset as the universe. Preset panel sources (Feature Selection, Candidate Genes, WGCNA modules) can be selected instead of pasting. Tables show p-values, adjusted p-values, q-values and the overlapping genes. Gene cards are fetched from MyGene.info, and a STRING protein-interaction network (Szklarczyk et al., 2023) with a degree table is drawn for the list.

**2.4.15 Immune deconvolution**

Immune Deconvolution estimates immune-cell composition from bulk expression. Two estimators with different assumptions are run: CIBERSORT with the LM22 signature (Newman et al., 2015), through the IOBR package (Zeng et al., 2021) with a user-set permutation count, and the marker-gene-based MCP-counter (Becht et al., 2016). CIBERSORT is fed linear-scale values and MCP-counter log2 values, converted automatically. The user selects the metadata column defining groups and an optional sample filter. Outputs are per-sample fraction and abundance tables, group-comparison boxplots with significance annotations, and Wilcoxon rank-sum or Kruskal--Wallis tests (Kim, 2014), chosen by group count with a manual override, corrected by Benjamini--Hochberg at FDR 0.05. Agreement between the two estimators is a check on cell-composition findings.

**2.4.16 Nomogram**

The Nomogram sub-module fits a logistic regression to a 2 to 12-gene panel with the rms package (Harrell, 2015), separately for females and males (and optionally pooled), on either the blood or the synovium cohort; the blood path requires at least 30 complete samples per sex and 10 per group, the synovium path 10 per group. A ridge penalty can be chosen by pentrace. Four tabs show a points-based nomogram, a calibration plot of predicted versus observed probability, a decision curve of net benefit against treat-all and treat-none (Vickers & Elkin, 2006), and a clinical-impact plot of patients flagged high-risk per N with the number of true cases, with bootstrap 95 % bands (Efron & Tibshirani, 1993). The decision-curve and clinical-impact tabs export CSV; the coefficient table and fitted model object are downloadable separately. The panel can be pasted or taken from the same-tissue consensus, cross-tissue or cross-ancestry results, so that a panel identified elsewhere can be assessed for clinical utility.

**2.4.17 Biomarker Card (transcriptomics)**

The transcriptomics Biomarker Card is a read-only interpretation layer for a single gene or a multi-gene panel. Its eight sections assemble the gene\'s identity and annotation (NCBI Gene, UniProt, Gene Ontology), pathways (KEGG, Reactome, WikiPathways), target and disease evidence (Open Targets, Human Protein Atlas), interactions and druggability (STRING, DGIdb), literature (PubMed), and the in-session results from differential expression, candidate gene identification, feature selection and classification. Evidence is summarised in four tiers: insufficient evidence, candidate biomarker, supported candidate (diagnostic or biological evidence plus internal cross-validation) and strong candidate, which additionally requires that a panel containing the gene has been scored on an external cohort with frozen models in the Diagnostic Model\'s External Validation tab during the session; the card reads that result from the shared session results and shows the per-model external AUCs, and the tier is never reached from training or cross-validation evidence alone. External queries are cached for the session.

**2.5 Methylomics module**

**2.5.1 Dataset**

The Methylomics Dataset sub-module accepts three input routes: a bundled reference, an upload, and a GEO fetch, the upload route accepting either a processed matrix or raw IDAT files. The bundled reference is the GSE42861 whole-blood RA cohort (689 samples, Illumina 450K; Liu et al., 2013). Its full beta matrix (about 2.1 GB) is read in a background task so that the rest of the application stays responsive while it loads; when a deployment ships only the metadata and precomputed tables, the Dataset tab says so and the sub-modules that need the matrix fall back to their precomputed views. Uploads are a beta- or M-value matrix as CSV, TSV, TXT or RDS, with probes as rows and samples as columns, plus a sample sheet; the user declares beta or M scale and the declaration is validated against the value range. A matrix whose rows and columns are the wrong way round is detected from probe-identifier patterns and transposed automatically, duplicated probe identifiers are rejected in delimited files and collapsed to the first occurrence in RDS files, and a matrix declared as beta values is refused when fewer than 95 % of its finite values lie in \[−0.05, 1.05\], whereas a matrix declared as M-values that looks like beta values only triggers a warning. The user also declares the array type (450K, EPIC, EPICv2, WGBS, RRBS or custom array); Illumina manifest annotation is wired up only for 450K (ilmn12.hg19) and EPIC v1 (ilm10b4.hg19), so the SNP, non-CpG and sex-chromosome probe filters and the annotation-based sex check are unavailable for the other types, and the Dataset tab states this for EPICv2. Raw IDAT files are read as paired green and red channels into an RGChannelSet and a MethylSet (minfi::read.metharray.exp() followed by preprocessRaw()), with the array type detected automatically from the files and overriding the declared type when they disagree, yielding unnormalised beta values, detection p-values and bead counts while retaining the raw intensities for checks that a processed matrix cannot support. GEO fetch recognises the 27K, 450K, EPIC and EPICv2 platforms (GPL8490, GPL13534, GPL21145 and GPL33022), lets the user pick a platform when a series spans several, and accepts a custom array when at least 95 % of values fall in \[−0.05, 1.05\]; a recognised platform whose values fail the same range check is loaded with a warning that the deposited matrix may be M-values or unprocessed intensities. One dataset is active at a time and loading a new one replaces the previous one and clears dependent results. Several downstream sub-modules nevertheless accept their own inputs independently of the active dataset: Cell-Type Deconvolution takes its own matrix so that a reference-based estimate can be produced for data that are not the active dataset, and Feature Selection, the Diagnostic Classifier, Validation, Candidate CpGs, Mendelian randomisation, colocalisation and the Biomarker Card each have an upload route for the tables they consume.

**2.5.2 Quality control**

Quality Control comprises eight tabs reading the same matrix. Every live analysis runs on a chosen stratum: all samples, or one level of a chosen sample-sheet column such as sex; probe QC needs at least three samples in scope and outlier detection at least four. For the bundled cohort the **Overview** tab reproduces the completed pipeline\'s QC as a historical record rather than recomputing it: cohort composition by sex, PCA outliers (more than 5 MAD, assessed within each sex because whole-blood methylation separates strongly by sex on the leading components), chromosome-Y sex mismatches, and a five-step probe-filtering cascade (cg-prefix restriction, MASK_general removal (Zhou, Laird & Shen, 2017), multi-hit removal, sex-chromosome removal and more than 5 % missingness) that reduced 485,577 probes to 412,492. <span style="color:purple">A 2026-09-08 regeneration check found the chromosome-Y sex-mismatch figures cannot be reproduced from the bundled raw matrix (it already has zero sex-chromosome probes) and the PCA outlier flags do not reproduce numerically (regenerated PC1/PC2 uncorrelated with the shown values, r ≈ 0.05; no sample flagged as an outlier by both runs) - see the reproducibility check note above.</span> For live data **Overview** reports a pass, warning or fail status with call-rate and missingness statistics. **Sample QC** adds bisulfite-conversion efficiency, median intensity and failed-probe percentage when IDAT data are available (defaults: minimum call rate 0.95 at a per-probe detection p-value of 0.01, at most 5 % failed probes, minimum median log2 intensity 10). **Probe QC** applies eleven filters in a fixed order: detection p-value, bead count, SNP overlap, non-CpG probes, sex-chromosome probes, cross-reactive probes (Zhou, Laird & Shen, 2017), minor allele frequency, missingness, variance, standard deviation and mean-value range. Each filter is evaluated on the full matrix and the retained set is their intersection; the retention flowchart shows the cumulative count after each filter in that order. By default the SNP, non-CpG and missingness (no missing values allowed) filters are on, the detection p-value (0.01) and bead-count (3) filters are on only when IDAT data exist, sex-chromosome probes are kept (with \"remove X and Y\" and \"remove Y only\" as alternatives), and the remaining filters are off. The SNP, non-CpG and sex-chromosome filters need the Illumina manifest and are hidden for other array types. The cross-reactive and MAF filters act only when the user uploads a probe list; no list is bundled. **Sex QC** infers sex from raw-intensity copy number with minfi::getSex() when IDAT data exist (Aryee et al., 2014) and from a k-means split of chromosome-Y beta values otherwise, with the label direction inferred from the reported sex; with fewer than six samples a median split replaces k-means, without a reported sex the higher-chromosome-Y cluster is assumed male, and discordant samples can be sent to the manual exclusion list. **Batch QC** compares principal-component structure before and after ComBat on M-values (Johnson, Li & Rabinovic, 2007) or RUVm, which requires IDAT data (Maksimovic et al., 2015), and blocks correction when batch and phenotype are confounded (a chi-square test between the batch column and the chosen phenotype column) unless the user ticks an explicit override. ComBat needs a batch column with at least two levels of at least two samples each and returns the corrected values on the input scale; RUVm estimates unwanted variation from the array\'s internal negative-control probes with missMethyl (RUVfit with the ruv4 method, then RUVadj), protecting a chosen factor of interest, with k = 1 by default. The corrected matrix is offered as a download and is not written to the active dataset. **Outlier QC** offers PCA, hierarchical clustering, correlation and Mahalanobis distance, combined into a consensus score, so that the user can pick methods appropriate to the sample size (defaults: 3 SD on the principal components, a singleton height fraction of 0.5, a MAD multiplier of 3 for correlation, and α = 0.01 for Mahalanobis distance, all on the 5,000 most variable probes; nothing is excluded automatically). **Visualizations** plots the filtered matrix, and **Reports & Export** aggregates all results into an HTML report with embedded figures, a PDF (offered only when a LaTeX toolchain is installed), a ZIP archive and the R code that reproduces the run, together with CSV downloads of the filtered beta and M-value matrices and the per-sample and per-filter summaries. A manual include/exclude table propagates sample decisions to every tab. Quality Control is entirely non-destructive: it never modifies the active dataset. Probe filters and sample exclusions apply within its own tabs and the filtered and batch-corrected matrices are downloads; to carry a filtered matrix forward the user re-uploads it or applies the Normalisation tab\'s filters and promotes the result (Section 2.5.3).

**2.5.3 Normalisation**

The bundled cohort is distributed already normalised (Liu et al., 2013) and is not re-normalised, since doing so would change the published reference results; the tab states this, although the Type I versus Type II diagnostic described below is still computed on the bundled matrix and reported as a technical note. For uploaded matrices or IDAT files, three tabs follow. A **Filters** tab offers, all off by default, probe and sample missingness thresholds (5 % and 10 %), a minimum per-sample detection rate (IDAT only), and, for Illumina arrays only, removal of SNP-overlapping probes, cross-reactive probes (uploaded list), sex-chromosome probes and chosen chromosomes, and restriction by CpG-island relation or gene region; **Method & Run** is followed by a choice among eleven options: stratified quantile normalisation (Touleimat & Tost, 2012), dasen (Pidsley et al., 2013), functional normalisation (Fortin et al., 2014), SWAN (Maksimovic, Gordon & Oshlack, 2012), Noob (Triche et al., 2013), Noob followed by SWAN, Noob followed by BMIQ, a plain, non-stratified quantile normalisation (Bolstad et al., 2003), BMIQ (Teschendorff et al., 2013), peak-based correction (Dedeurwaerder et al., 2011), and no normalisation. Availability depends on the input: the raw-intensity methods (stratified quantile, dasen, functional normalisation, SWAN, Noob and Noob + SWAN) need IDAT data, Noob + BMIQ needs IDAT data and a manifest, BMIQ and peak-based correction need a manifest and a beta-scale matrix, and plain quantile normalisation and \"no normalisation\" are always offered. These are implemented through minfi (Aryee et al., 2014), wateRmelon (Pidsley et al., 2013), ChAMP (Tian et al., 2017) (for peak-based correction only) and limma (for the plain quantile method). A Kolmogorov--Smirnov diagnostic of Type I versus Type II probe bias drives a recommendation engine that is advisory only: it pre-selects \"no normalisation\" when no bias is detected, otherwise Noob when raw intensities exist and BMIQ when they do not, and every compatible method remains selectable, a **Compare Methods** tab runs several methods side by side, computation runs in a background callr process, and a biological-signal preservation guard , enabled by choosing a phenotype column, fits the first principal component on that phenotype before and after normalisation and warns when the variance explained (R²) drops by more than 50 % from a starting value above 0.05. Each run also reports mean probe variance, missingness, mean inter-sample correlation and the Type I/II statistic before and after. The normalised matrix becomes the active dataset for every downstream sub-module only when the user clicks \"Use this as the active Methylomics dataset\"; otherwise it is available as a download and the active dataset is unchanged.

**2.5.4 Cell-type deconvolution**

Cell-Type Deconvolution estimates the proportion of each cell type in a bulk sample from its methylation profile (Nguyen et al., 2024) through seven tabs: Data & QC, CpG Feature Selection, Reference & Method, Deconvolution, Cell Composition, Validation and Export. Filters applied before estimation are SNP-associated probes (Pongpanich, Sullivan & Tzeng, 2010), cross-reactive probes (Hop et al., 2020), detection p-value (IDAT only; Heiss & Just, 2019), a missing-CpG threshold (Di Lena et al., 2019), sex-chromosome removal (Khramtsova et al., 2023) and a missing-sample threshold, with probe and sample counts reported at each step. Defaults are 5 % missing per CpG, 10 % missing per sample, autosomes only, and beta-range validation on; the SNP, cross-reactive and detection-p-value filters are off, and the cross-reactive filter needs an uploaded list. Marker CpGs come from the chosen reference library (each CpG assigned to the cell type it best distinguishes, ranked by between-type effect and specificity, with the top N, 200 by default, balanced across cell types and optional direction, specificity and chromosome restrictions), from variance ranking, or from a custom list; selection from differentially methylated markers is listed as unavailable because the built-in references are mean-beta centroids without replicates. Estimation uses the EpiDISH engine (Zheng et al., 2019) with constrained projection (Houseman et al., 2012), robust partial correlation, CIBERSORT-style support vector regression, or the two-stage hierarchical variant, against one of seven built-in references, namely the Reinius/Houseman seven-cell blood reference, a compact seven-cell blood panel, the Salas twelve-cell reference (Salas et al., 2022), a 450K-restricted twelve-cell panel, an extended nineteen-subtype blood panel, and two epithelial/fibroblast/immune references with and without adipocytes, or a custom reference. Deconvolution needs at least ten marker CpGs shared between the matrix and the reference and a marker-overlap gate refuses references with insufficient probe coverage (50 % by default, adjustable to 90 %). Results run only when the user clicks Run and are then handed to the DMP sub-module as selectable cell-type covariates; the DMR and WGCNA sub-modules do not read them (WGCNA uses cell-type columns present in the sample sheet). Validation reports reconstruction error (correlation, RMSE, MAE and R² between the observed matrix and the matrix reconstructed from the estimated fractions, overall and per sample) and a Compare Methods panel that re-runs CP, RPC and CBS on the identical input with a method-correlation heatmap, an agreement table and Bland--Altman comparisons between methods. MethylResolver, IDOL and reference-free methods are listed explicitly as not available.

**2.5.5 Differentially methylated positions**

The DMP sub-module has two tabs. The **SVA** tab fits a limma model on M-values for the chosen group comparison (reference and comparison level of a chosen sample-sheet column, on all samples or within one sex), estimates surrogate variables on the 20,000 most variable probes with sva::sva() (iteratively re-weighted method) against a null model of the chosen covariates, appends them to the design and drops trailing surrogate variables until the design is full rank (Leek et al., 2012), carries cell-type fractions forward as covariates when available (they appear as selectable covariates once Cell-Type Deconvolution has run, and when every fraction is selected the one with the highest mean is dropped as the implicit reference to avoid a singular design), corrects the resulting test statistics for bias and inflation with bacon (van Iterson et al., 2017) and applies Benjamini--Hochberg FDR to the bacon-corrected p-values; the pre- and post-correction genomic inflation factors are reported. Effect sizes are reported as Δβ on the beta scale. A run needs at least six matched samples and three per group; probes are pre-filtered by a minimum valid-sample percentage (80 % by default), an optional minimum variance and an optional manifest-based SNP filter. The **DMP** tab fits the same limma group model without surrogate variables or bacon, for a direct, unadjusted view. Both tabs filter by FDR, minimum Δβ, direction (hyper- or hypomethylated), valid-sample percentage, variance and SNP overlap. For the bundled cohort, the SVA tab reproduces the precomputed sex-stratified analysis: limma on M-values with group, age, smoking status and estimated cell-type fractions, fitted separately in women and men, bacon-corrected and Benjamini--Hochberg adjusted. <span style="color:purple">A 2026-09-08 regeneration from the raw matrix through the app's own SVA/bacon code reproduces the statistics closely (t-statistic r = 0.955 female / 0.976 male; Δβ r = 1.000 / 0.9997 against the values shown here) but not the small FDR &lt; 0.05 CpG counts themselves (female: 18 shown vs 11 regenerated, 11 in common; male: 0 vs 0) - see the reproducibility check note above.</span> The unadjusted precomputed model is summarised alongside it; that model retained residual genomic inflation after bacon correction in both sexes, and the SVA-adjusted panel is the one carried into DMR calling, Candidate CpGs and the Biomarker Card. Live results from either tab are stored for the Cross-Omics Dataset sub-module (Section 2.6.1), the most recent run replacing the previous one; an SVA-tab run is handed on with its bacon-corrected p-values and the dataset\'s declared array type, so that Cross-Omics can annotate its CpGs from the matching Illumina manifest.

**2.5.6 Differentially methylated regions**

The DMR sub-module mirrors DMP with an **SVA** tab and a plain **DMR** tab, both calling regions with DMRcate (Peters et al., 2015) from per-CpG limma statistics, with bacon correction on the SVA tab. CpGs with a bacon-corrected p-value below 0.05 (raw p-value on the plain tab) seed candidate regions; regions are formed with a kernel bandwidth λ of 1,000 bp and scaling factor C = 2, require at least three CpGs, and are then filtered by region-level FDR (0.05), minimum absolute mean Δβ (0.05 on the live SVA tab), direction and region width. The advanced settings expose λ, C and a manual candidate-region cutoff in place of DMRcate\'s FDR default. For the bundled cohort the SVA tab shows the precomputed sex-stratified DMRcate run (λ = 1,000, C = 2, hg19) on the SVA-adjusted, bacon-corrected statistics. <span style="color:purple">Feeding a 2026-09-08 end-to-end regeneration's own DMP statistics into this DMRcate pipeline recovers 64.2 % of the female and 62.9 % of the male regions shown here by genomic overlap (57.1 % / 57.2 % of the FDR &lt; 0.05 ones), a partial rather than exact reproduction, expected from DMRcate's sensitivity to input p-values that themselves correlate at r ≈ 0.96-0.98 rather than 1 - see the reproducibility check note above.</span> Probe chromosome, position and SNP annotation come from the Illumina manifest packages for 450K (ilmn12.hg19) and EPIC (ilm10b4.hg19); coordinates are hg19 and no other build is supported, so regions cannot be called for EPICv2 or non-Illumina data. Overlaps between regions and probes are computed with GenomicRanges, IRanges and S4Vectors (Lawrence et al., 2013). Both tabs re-execute against the current dataset and store the region table for the Candidate CpGs sub-module.

**2.5.7 Sex interaction analysis (methylomics)**

The methylomics twin of Section 2.4.11 fits a limma model of group × sex plus covariates on M-values and returns the same four coefficients from a single fit: interaction, disease effect within each sex, and sex main effect. Δβ is reported per cell, the design is checked for rank (constant or single-level covariates are refused and a rank-deficient design stops the run), per-cell counts are shown, and a power warning with the minimum detectable effect (in M-value standard deviations at 80 % power and α = 0.05, before multiple-testing adjustment) appears when a cell has fewer than ten samples. A run needs at least twelve samples and two per group-by-sex cell, samples missing a chosen covariate are dropped, and results are filtered at an adjusted p-value of 0.05. There is no precomputed route: the sub-module runs live on the active dataset, including the bundled matrix.

Cell-type composition is treated inconsistently across these three sibling sub-modules. DMP is the only one of the three that consumes the deconvolution output directly: estimated cell-type fractions become selectable covariates once Cell-Type Deconvolution has run, and are folded into both the SVA and precomputed models. DMR never adjusts for cell-type composition and instead relies on the same sva::sva() step as DMP to absorb unmeasured confounding. Sex Interaction adjusts for neither: it has no automated confounder-absorption step of any kind, offering only user-selected sample-sheet covariates, with no surrogate-variable or cell-type adjustment applied unless a user happens to add a covariate that encodes one. This is not a defect internal to any one sub-module, but it does mean the same disease effect can be adjusted for cell composition and unmeasured confounding in one context and, in another, adjusted for neither.

**2.5.8 WGCNA co-methylation network**

The co-methylation network sub-module (Zhang & Horvath, 2005; Cheng et al., 2022) has seven tabs: Data & Filtering, Sample QC, Soft Threshold, Network & Modules, Module--Trait Analysis, Hub CpGs, and Results & Export. Data & Filtering selects the stratum (one sex or all samples; Female by default for the bundled cohort, all samples for uploads, with at least six samples required and a warning below fifteen), removes CpGs with excess missingness (more than 5 % by default), regresses out any sample-sheet columns chosen as covariates on the M-value scale with limma (age, smoking status and cell-type fractions are pre-ticked for the bundled cohort, leaving the cell type with the highest mean fraction unticked as the implicit reference; Cote, Young & Huckins, 2022) and keeps the most variable CpGs by MAD, variance, standard deviation or IQR (top N default 20,000 for the reference, 5,000 for uploads). Sample QC is diagnostic only. Soft Threshold evaluates powers for scale-free fit (signed, signed-hybrid or unsigned network, signed by default; biweight midcorrelation by default for uploads and Pearson for the bundled cohort, matching the published run; target R² 0.85), Network & Modules builds the TOM and cuts modules with blockwiseModules (maximum block size 5,000; minimum module size 20 for the bundled cohort and 30 for uploads; deepSplit 2; merge cut height 0.25; PAM refinement; seed 1,234), caching the bundled cohort\'s blocks on disk, and Module--Trait correlates module eigengenes with a chosen trait by Pearson or Spearman correlation, with Benjamini--Hochberg or Bonferroni correction; columns already regressed out as covariates are excluded from the trait choices, and sex stratification is set on the Data & Filtering tab rather than here. Hub CpGs are those with kME ≥ 0.7 (default). Results & Export provides CSV downloads, an enrichment of each trait-significant module, by a two-sided Fisher\'s exact test with Benjamini--Hochberg correction across modules, against the bundled sex-specific DMP/DMR biomarker panel from the published pipeline (not against the session\'s own DMP and DMR results), and a comparison with published module--trait tables.

**2.5.9 Candidate CpGs (module--DMR overlap)**

This sub-module combines co-methylation modules with differentially methylated regions across five tabs. **Data and filters** takes the WGCNA module assignments, a DMR table (chromosome, start, end) and CpG coordinates from the live session, from files, or from the bundled results (the published per-sex module assignments, DMR table and SVA-adjusted CpG statistics), with fuzzy column detection, and sets the module and DMR significance cutoff (module selection, minimum module size and \|kME\|, exclusion of the grey module by default, DMR FDR ≤ 0.05, raw p-value, minimum \|Δβ\|, minimum CpGs per region, direction, an \"inside\" or flanking-distance overlap definition, chromosome restriction and, when both sides carry a direction, direction consistency). **DMR--CpG Overlaps** finds CpGs inside regions by genomic-range intersection (Lawrence et al., 2013). **Module--DMR Overlap** runs a one-sided Fisher\'s exact test per module for enrichment of DMR-overlapping CpGs, with Benjamini--Hochberg FDR. **Candidate CpGs** filters by module, significance, effect size, direction, consistency and genomic context, and ranks by significance, effect size, module membership or a combined score (−log10 of the CpG and DMR FDR capped at 10, ten times the absolute CpG and DMR Δβ, the absolute kME, and one point for direction consistency, summed according to the chosen mode). **Visualisation** offers six views (overlapping CpGs per module, a module-enrichment heatmap, candidate CpGs per DMR, effect direction, genomic-annotation distribution and a candidate volcano plot).

**2.5.10 Mendelian randomisation (methylomics)**

The methylomics MR sub-module has eight tabs. **Data** takes an exposure file of SNP--CpG mQTL summary statistics and an outcome GWAS, or the bundled GoDMC mQTL (Min et al., 2021) against the Ishigaki et al. (2022) RA GWAS, for the female stratum, the male stratum or their union. **Instrument selection** applies F ≥ 10, p \< 5 × 10⁻⁸, a cis window of 1 Mb around the CpG and a MAF filter (off by default); weak instruments are flagged and, by default, excluded, and the number of instruments per CpG can be bounded. **LD clumping** keeps independent instruments per CpG through the OpenGWAS API (ieugwasr::ld_clump(); r² \< 0.001 within 10,000 kb, European reference by default); no local PLINK reference is bundled, and if the API cannot be reached the analysis proceeds on the unclumped set with a note. **Harmonisation** aligns effect alleles between exposure and outcome with TwoSampleMR (Hemani et al., 2018); the default action infers strand from allele frequency, and removal of palindromic SNPs is an optional stricter setting. **Estimation** uses inverse-variance weighting (Burgess, Butterworth & Thompson, 2013), MR-Egger (Bowden, Davey Smith & Burgess, 2015), weighted median (Bowden et al., 2016), and weighted and simple mode (Hartwig, Davey Smith & Bowden, 2017) for three or more instruments, the Wald ratio for a single instrument and IVW alone for two, with MR-PRESSO (Verbanck et al., 2018) (off by default, four or more instruments) and MR-RAPS and the penalised weighted median offered when the installed TwoSampleMR version provides them; contamination-mixture and radial MR are not wired in. **Sensitivity** reports single-SNP estimates, heterogeneity, pleiotropy, leave-one-out and Steiger directionality (Hemani, Tilling & Davey Smith, 2017), the last requiring sample sizes in both files. **Results** lists causal estimates per CpG with FDR or Bonferroni adjustment, and **Plots** shows scatter, forest, funnel, leave-one-out, single-SNP and Manhattan plots. On the bundled route the instrument set is cached exactly as the published pipeline built it (cis-restricted, clumped against GoDMC\'s own reference and harmonised with the default strategy) and is not rebuilt; the MR estimates and sensitivity analyses are then recomputed live from that cached set with TwoSampleMR.

**2.5.11 Colocalisation (methylomics)**

Six tabs test whether an mQTL and a GWAS signal share a causal variant. **Data and setup** accepts uploaded mQTL and GWAS summary files, one row per SNP with identifier, effect size, standard error, p-value, effect and other allele and sample size, plus allele frequency for the (quantitative) methylation side, or the bundled data. The GWAS is declared binary (with a case-fraction slider, 0.33 by default) or quantitative, and the methylation side is analysed as a quantitative trait with the median reported sample size. **Filters and parameters** restricts to a genomic window (±1,000 kb around the lead SNP or a given position), bounds allele frequency, sets separate p-value thresholds, a minimum sample size, removes ambiguous and duplicate variants, and edits the priors p1, p2 and p12 (coloc\'s defaults of 10⁻⁴, 10⁻⁴ and 10⁻⁵), and requires at least ten shared SNPs. Datasets are harmonised to a common effect allele with TwoSampleMR, inferring strand from allele frequency by default. **Results** reports PP.H0 to PP.H4 from coloc.abf (Giambartolomei et al., 2014), or coloc.susie when LD matrices are supplied for both datasets, with a supported, refuted or inconclusive verdict at an adjustable posterior threshold of 0.8, the value used by the published pipeline. **Visualisation** shows a regional plot (which needs SNP positions), a two-signal comparison and a ranking of variants by shared-signal support; **Sensitivity** re-runs the analysis under alternative priors (coloc\'s own p12 sensitivity curve over a grid of 100 values) and filters (one filter varied at a time); **Export** downloads everything. Only the per-CpG PP.H0 to PP.H4 summaries of the published GoDMC-versus-Ishigaki run are bundled, not the per-SNP regional data, so the bundled route is a cached look-up and cannot re-run coloc.abf or draw regional plots.

**2.5.12 ML feature selection**

Feature Selection has nine tabs and is run separately for Female, Male and Pooled samples, on the active dataset or on its own uploaded matrix and phenotype file. **Data preparation** removes CpGs with more than 5 % and samples with more than 20 % missing values, imputes remaining missing values (per-probe median by default, k-nearest neighbours when the impute package is installed) and applies optional filters for low variance, cross-reactive probes and high MAF (both require an uploaded list), sex-chromosome probes and SNP-associated probes (the last two off by default), then takes a seeded held-out split before any selection (30 % by default, stratified by group with caret, seed 1,234; the training portion must keep at least six samples and two per group). By default only the 5,000 most variable CpGs are carried into selection. **Univariate** ranks CpGs by t-test, moderated t-test (Smyth, 2004), ANOVA, Wilcoxon, Kruskal--Wallis, linear regression, Pearson or Spearman correlation (Lecocke & Hess, 2007). **Penalised regression** fits LASSO, elastic net or ridge through an α slider (Tibshirani, 1996; Friedman, Hastie & Tibshirani, 2010), with λ chosen by 10-fold cross-validation at lambda.min or lambda.1se, optional balanced class weights and a cap of 200 selected CpGs by default. **Tree-based** ranks by random-forest importance (Breiman, 2001) (mean decrease in Gini, top 50 by default). **RFE** performs recursive elimination (Guyon et al., 2002) with caret\'s random-forest or logistic-regression functions, or SVM-RFE. **Stability selection** repeats the selection over resamples (Meinshausen & Bühlmann, 2010) (a glmnet fit at a fixed λ over 50 bootstrap, subsampling or repeated k-fold resamples of 80 %, keeping CpGs selected in at least 70 %). **Consensus** intersects the methods (at least two methods by default, or a weighted score), **Selected features** reduces collinearity (dropping the lower-scoring member of any pair with \|r\| \> 0.8), and **Model & Export** runs a quick or repeated nested cross-validation check (nested by default, with logistic regression, random forest or SVM in five folds, and stated to be within the training partition only) and saves the panel as RDS with a checksum and a leakage-safe flag that the Diagnostic Classifier reads, together with the held-out sample identifiers so that the classifier can apply the same split.

**2.5.13 Diagnostic classifier**

The Diagnostic Classifier opens with three setup tabs. **Datasets** loads either the bundled panel data (a cell-type-adjusted internal panel from GSE42861 restricted to the 21 majority-vote panel CpGs, 12 female and 9 male, with a sex stratum that defaults to Female) or an uploaded matrix and sample sheet, and takes a stratified training split (75 % by default, seed 42). **Feature Source** takes its features from the WGCNA modules (the bundled module assignments, or an uploaded module table), Feature Selection (the bundled ensemble-vote table with a minimum of two of three votes, or that module\'s RDS export), an uploaded CpG list, or a manual CpG selection. **Filters & Parameters** chooses single-CpG or combined-panel analysis, imbalance handling (none, fold-safe up-sampling or fold-safe SMOTE), the repeated cross-validation scheme (10 folds, one repeat by default), grid or randomised search, and the threshold strategy (0.5, Youden\'s J, or a sensitivity- or specificity-focused target of 0.90). Six classifier tabs each fit one algorithm with repeated cross-validated tuning: support vector machine with linear, radial or polynomial kernel on centred and scaled features (Cortes & Vapnik, 1995) (radial by default), penalised logistic regression with an L1/L2 switch (L2 by default), elastic net (Greenwood et al., 2020) with automatic hyperparameter search, gradient boosting through XGBoost\'s native grid search (Chen & Guestrin, 2016) with early stopping (SMOTE is not available for this model), random forest with adjustable tree count and mtry (Breiman, 2001) (500 trees by default), and k-nearest neighbours over a range of k (Uddin et al., 2022) with uniform weights and Euclidean distance. Each reports training, cross-validated and internal-test AUC with DeLong intervals (Robin et al., 2011), sensitivity, specificity, Matthews correlation coefficient, precision--recall AUC, Brier score, calibration and learning curves. Class imbalance is handled inside folds by up-sampling or SMOTE (Chawla et al., 2002) and several threshold strategies are offered. As in the transcriptomics module, a leakage-safe nested cross-validation estimate replaces the split estimate whenever the feature panel was not selected on a held-out basis. A run counts as leakage-safe only when a Feature Selection RDS export carrying held-out sample identifiers is uploaded and those identifiers are applied as the test split; the bundled panels, WGCNA modules, uploaded lists and manual selections are never leakage-safe, so for them the nested-CV AUC (reselecting the panel with a moderated t-test and LASSO inside every outer fold) is the headline and the split AUC is labelled exploratory. **Model Comparison** contrasts completed runs across models and panels, including single-CpG versus panel results; **Test Internal Data** reports sample counts and feature overlap between splits; **Export** downloads CSV. Trained models are passed to the Validation sub-module.

**2.5.14 Validation**

The Validation sub-module applies classifiers trained in the Diagnostic Classifier to an independent cohort (the bundled external cohort of 43 female samples or an upload). The bundled cohort is GSE111942 (Zhu et al., 2019): 25 RA cases and 18 controls, PBMC, Illumina 450K, all female, processed upstream with Noob and adjusted for granulocyte content so that its preprocessing matches the training cohort. Because it contains no men, male-stratum models cannot be validated on it and an uploaded cohort is required instead. A seven-row compatibility check confirms the same value representation, CpG set, reuse of the training scaling, normalisation provenance, treatment of missing values (excluded, not imputed), reuse of the decision threshold, and platform, and a sample-independence check guards against overlap with the training data. Samples missing any required CpG are excluded from scoring. Each model is reported with AUC and 95 % confidence interval, sensitivity, specificity and accuracy (Çorbacıoğlu & Aksel, 2023), the last three with 1,000-resample bootstrap intervals, with ROC and calibration plots, downloadable as CSV or PNG, alongside a Model Comparison tab and a Test External Data tab that reports the cohort\'s sample counts and feature overlap.

**2.5.15 Biomarker Analysis (methylomics card)**

The methylomics card summarises a CpG or gene drawn from the bundled results or from the active dataset, found by CpG identifier, gene symbol, browsing the bundled DMP results or the diagnostic panel of either sex, or uploading a list; a multi-biomarker list opens a panel view with overview, disease/trait and pathway convergence, and source tabs instead of a single card. The card itself has eight sections: CpG description, biomarker status, dataset, differential methylation (DMP/DMR), single-gene versus multi-gene signature, biomarker performance, external databases and download. Biomarker status is an eight-row yes/no evidence checklist (significance in the user\'s dataset, gene association, CpG-island or regulatory annotation, evidence in both sexes, independent EWAS replication, RA evidence, pathway association, and methylation--expression evidence, the last always reported as not yet integrated) and the external section queries fifteen external sources (EWAS Catalog, EWAS Atlas, NCBI Gene, Ensembl (GRCh37) and its Regulatory Build, KEGG, Reactome, WikiPathways, Open Targets, GWAS Catalog, Human Protein Atlas, ENCODE, GEO, BioStudies/ArrayExpress and PubMed), recording a retrieval timestamp for every query so that the report is auditable. It does not compute an evidence tier; the only graded label is Open Targets\' drug-tractability category. Sources considered but not integrated (DisGeNET, GTEx, OMIM and the Human Phenotype Ontology) are listed with the reason.

**2.6 Cross-omics module**

The Cross-Omics vertical consists of a Dataset tab and three sub-modules that the user adds from a Sub-modules gallery: Expression and Methylation (the gene-level integration described in 2.6.2), Biomarker Convergence and Cross-Omics MR. Only Expression and Methylation consumes what the Dataset tab loads. Biomarker Convergence and Cross-Omics MR read the project\'s precomputed convergence tables or the user\'s own uploads, are independent of the Dataset tab and of the integration result, and are linked to each other only in that Cross-Omics MR reuses the evidence table that Biomarker Convergence has loaded. Every computation in this vertical is synchronous, and, <span style="color:purple">as of 2026-09-08, all three sub-modules write to the session analysis-record log (Section 4.3)</span>.

**2.6.1 Dataset**

The Cross-Omics Dataset sub-module has two modes. *My analysis results* takes a chosen live differential-expression run (any run of the session, selected by its contrast label, the most recent one by default) and the most recent live differential-methylation run of the session; the load button appears only when both exist. The methylation input is the per-CpG table published by whichever tab of the methylomics DMP sub-module ran last, the SVA tab or the plain DMP tab (Section 2.5.5); live DMR results are not accepted on this route. The differential-expression run carries only the gene, log2 fold change and adjusted p-value, so the expression FDR used downstream is the one limma or DESeq2 already computed; the DMP table carries CpG, gene, Δβ, p-value (the bacon-corrected p when the run came from the SVA tab, so that it agrees with that tab\'s FDR), FDR, chromosome and position, and CpGs with no gene annotation are dropped. Gene-feature and CpG-island context are filled in from the Illumina manifest when the active methylomics dataset is declared as 450K or EPIC, so that the region-restricted aggregation rules and island filters of 2.6.2 work on this route; for other array types they remain blank. *Upload* accepts CSV, TSV, TXT or XLSX files (first sheet only for XLSX), with columns recognised automatically from their names: the expression table needs a gene column and a log2 fold-change column, the methylation table a gene column and a Δβ column; CpG identifier and p-value or FDR columns are optional but enable the significance-based views. Chromosome, position, region identifier, CpG count, gene feature (for example a UCSC RefGene group column) and island-context columns are also recognised when present, whereas a file that carries only beta values and no Δβ column is refused, because per-sample beta values alone cannot yield a methylation change. Either file may be uploaded on its own, but the integration needs both. A file whose required columns cannot be recognised is refused with a notice that lists the recognised header names; there is no manual column-mapping fallback. Duplicated gene rows in the expression table collapse to the row with the smallest FDR (or p-value). All further columns of an uploaded file are retained, and if both files carry per-sample numeric columns that share at least three sample names, those columns are treated as paired sample-level measurements for the correlation of 2.6.2. A preview shows the standardised table and a histogram of log2 fold change or Δβ; \"Use this data\" writes the tables to the shared cross-omics container, \"Clear\" empties it, and switching mode discards the staged tables. Loading new data does not clear an integration already run; the result is replaced only when Run Integration is clicked again. The Dataset tab has no bundled or GEO route; the bundled cross-omics tables enter the vertical only through Biomarker Convergence and Cross-Omics MR (2.6.3, 2.6.4).

**2.6.2 Expression--methylation integration**

The Expression and Methylation sub-module has seven tabs: Expression data, Methylation data, Integration, Quadrant plot, Heatmap, Network analysis and Export, preceded by a data-source switch that offers the Dataset-tab tables or, as a shortcut equivalent to the *My analysis results* mode of 2.6.1, the live session results. Integration runs when the user clicks Run Integration on the Integration tab, with default thresholds of \|log2FC\| ≥ 0.585 and expression FDR \< 0.05, \|Δβ\| ≥ 0.02 and methylation FDR \< 0.05. Gene identifiers are harmonised in a fixed order, symbol, then Entrez, then Ensembl, then alias, through org.Hs.eg.db, so that only exact or alias-resolved matches are joined: symbols are matched case-insensitively, version suffixes are stripped from Ensembl identifiers, an alias is resolved only when it maps to a single symbol and is otherwise marked ambiguous, and unmatched or ambiguous identifiers keep their original text and are still joined on that text. Harmonisation is skipped, with a notice, when org.Hs.eg.db is not installed. After harmonisation the expression table is de-duplicated again and CpGs that now share a symbol are pooled. When a gene carries several CpGs, they are aggregated to one record by one of seven selectable rules; the default takes the mean Δβ and combines p-values with a direction-signed Stouffer Z followed by Benjamini--Hochberg correction, so that the aggregated effect and its significance describe the same set of sites, and only the minimum-FDR and maximum-\|Δβ\| rules use a single representative CpG. The median rule behaves like the mean rule, the Benjamini--Hochberg step of these two rules is fixed regardless of the sub-module\'s own adjustment setting, and the three region-restricted rules (promoter only, gene body only, promoter and gene body) first bucket each CpG\'s feature annotation into promoter (TSS200, TSS1500, 5′UTR, first exon, upstream) or gene body (body, exon, intron, 3′UTR, exon boundary) and stop with an error when no CpG carries that annotation. Alongside the aggregate, per-gene CpG counts are kept at the CpG level: total, significant, hyper- and hypomethylated, per feature, island, shore, shelf and open sea, and a primary feature. The two tables are then joined by gene with a full outer join, so genes present in only one layer are retained with the other layer missing; if a table has p-values but no FDR, the FDR is computed at this point by Benjamini--Hochberg or Bonferroni, as selected. Each gene first receives a quadrant category from the thresholds: Hyper + Down and Hypo + Up (the two inverse-direction combinations), Hyper + Up and Hypo + Down (same-direction), or Not significant. Each gene is then classified into one of six evidence tiers by the function cx_classify_evidence(), based on whether expression and methylation are significant and whether their directions are inverse or the same: *Strong candidate* (significant in both layers, inverse direction, and a significant negative sample-level correlation at FDR \< 0.05), *Moderate candidate* (significant in both, inverse direction, correlation unavailable or not significant), *Discordant* (significant in both but in the same direction, which does not fit the simple inverse model), *Expression-only*, *Methylation-only* and *Insufficient evidence*. Without paired samples the Strong candidate tier can never be assigned. If paired samples are detected, sample-level expression--methylation correlation is computed as well: this happens only on the Upload route, when both files carry per-sample columns sharing at least three sample names; per gene, sample values are averaged over duplicate gene rows, Pearson or Spearman correlation is tested with cor.test() across the shared samples, and the p-values are adjusted by the selected method. The live route never carries samples, so its integrations are always unpaired. Views are tables, a quadrant plot, a heatmap and a static gene--CpG network, with filters: summary cards (genes analysed, significant DEGs, significant differentially methylated genes, integrated genes and the four quadrant categories) act as category filters for the tables; advanced filters for gene feature, island status, evidence tier, minimum CpG count and correlation direction apply to the two data tables but not to the plots, which are governed by \"show non-significant\" and \"significant only\" toggles. The quadrant plot is an interactive plotly scatter of Δβ against log2 fold change coloured by category, with the thresholds as dashed lines, up to fifteen labelled integrated genes, a search box, and a click-through gene modal that lists the gene\'s CpGs with their feature, island context, Δβ and FDR. The heatmap is a pheatmap over a two-column log2 fold change and Δβ matrix for the top N genes by \|log2FC\| (default 30), all genes significant in both layers, or one category, with optional row clustering and none, row or column scaling. The network is a static igraph Fruchterman--Reingold layout of at most 40 genes and three CpGs per gene, and exports include CSV, TSV, XLSX, a CpG-level CSV, per-stratum CSVs (All, Female or Male; the stratum is inferred from whether the loaded source label contains \"female\" or \"male\", not chosen explicitly), a Markdown report that embeds a parameter and provenance block (sources, thresholds, aggregation, correlation and adjustment methods, sample matching, gene-annotation source, the methylation platform as declared for a live methylomics dataset, module version) and the twenty top integrated genes, a ZIP archive (results, report and quadrant PNG), and PNG, PDF and SVG quadrant figures; the heatmap exports as PNG and PDF only. The quadrant plot, the gene modal and the report state that the results are statistical associations and not evidence of a causal regulatory relationship. The gene table and summary counts are stored in the shared results container for ArthOChat.

**2.6.3 Biomarker convergence**

Biomarker Convergence loads the project\'s precomputed per-gene convergence table, which joins the pipeline\'s sex-stratified eQTL-MR, mQTL-MR, DEG, DMP and DMR results, and relabels its significance flags; it does not use the expression--methylation result of 2.6.2. The user selects Female, Male or Both from the project\'s bundled MR tables (43 female genes, 34 male genes; \"Both\" is the two sex-specific tables stacked, 77 rows over 53 distinct genes, not a pooled-sex analysis), or uploads eQTL-MR and mQTL-MR result files; at least one must be supplied, the eQTL-MR file requiring a gene column and the mQTL-MR file a gene column and an mQTL-MR p-value column, with odds ratio, p-value, FDR and MHC flag optional in the former and candidate CpG, chromosome, position and effect size optional in the latter. As deposited, the bundled tables list no gene that has both an eQTL-MR and an mQTL-MR instrument, so at load time the sub-module backfills the mQTL-MR columns from the Cross-Omics MR instrument file (best instrument per gene by p-value); after this, 30 female, 23 male and 53 stacked genes carry both. Uploads are merged on gene into the same schema; unless a file happens to include columns with the pipeline\'s DEG, DMP or DMR names, those layers are treated as not significant, and the sex chosen for an upload is a label only. When only one file is uploaded the eQTL--mQTL tab is empty, and the interface says so. Significance thresholds are fixed, not adjustable, and are printed on the panel: DEG FDR \< 0.05, DMP bacon-corrected FDR \< 0.05, DMR FDR \< 0.05 and nominal mQTL-MR p \< 0.05. For eQTL-MR the bundled table\'s own significance flag is honoured, so that the sub-module agrees with the pipeline\'s join (two bundled female genes, FCGR2B and RETSAT, are flagged significant at an eQTL-MR FDR of 0.053); an uploaded eQTL-MR file is thresholded at FDR \< 0.05 when it supplies an FDR column and otherwise every listed gene counts. Each gene also receives a count of supporting layers (eQTL-MR, DEG, DMP or DMR, mQTL-MR) from zero to four, and genes in the MHC region are flagged because linkage disequilibrium there inflates apparent convergence: the flag is the table\'s own MHC column (14 of the 32 female and 10 of the 25 male eQTL-MR panel genes), or the optional MHC column of an uploaded eQTL-MR file, and a banner counts flagged rows on the eQTL-MR and eQTL--mQTL tabs. The view has summary cards (genes in the union, in each panel, in both, DEG-significant, methylation-significant by DMP or DMR) and eQTL-MR, mQTL-MR, eQTL--mQTL and Downloads tabs, each table exporting to CSV and the whole table to CSV or XLSX. The relabelled table is stored in the shared results container and reused by Cross-Omics MR.

**2.6.4 Cross-omics MR**

Cross-Omics MR classifies each gene into five evidence categories that are not mutually exclusive, so a gene can appear in several, according to which layers carry genetic support: DEG--DMP--QTL, DEG--DMR--QTL, DEG--eQTL, DMP--mQTL and DMR--mQTL. The rules are DEG significant and DMP genome-wide significant and mQTL-MR significant and eQTL-MR significant; the same with DMR in place of DMP; DEG and eQTL-MR significant; DMP and mQTL-MR significant; DMR and mQTL-MR significant. The flags come from a gene-level evidence table, either the bundled convergence table for the chosen sex (reused from Biomarker Convergence when it has already been loaded for that sex, otherwise loaded and relabelled here at the same fixed thresholds) or an uploaded gene-level table with the same column names, in which any missing column is treated as not significant and never fabricated, and in which eQTL-MR significance is eQTL-MR FDR \< 0.05. With the bundled evidence the two DMP-based categories are empty, because a single bundled gene reaches genome-wide DMP significance, and every DMR--mQTL gene is also DEG- and eQTL-MR-significant (13 female and 6 male genes). The MR instrument table must be loaded for the categories to display, but it does not enter the rules. The bundled analysis is a Wald-ratio mQTL-MR of GoDMC instruments against the Ishigaki et al. (2022) RA GWAS: 283 single-SNP cis-mQTL instruments (one SNP per CpG, so every estimate is a Wald ratio) covering 30 genes, run for the genes that were eQTL-MR-significant, with the outcome recorded in the file as the European-ancestry Ishigaki et al. (2022) meta-analysis (GCST90132223). Each row carries the estimate, standard error, p-value, odds ratio with confidence interval, Benjamini--Hochberg FDR, instrument SNP and the Steiger direction test with its p-value; 221 rows pass FDR \< 0.05 and 8 fail the Steiger test. Instruments are not aggregated per gene, no heterogeneity test is possible for single-instrument genes, and no instrument-strength statistic is available from the precomputed file, all of which the results table states. Uploaded MR results need gene and p-value columns; CpG, SNP, instrument count, effect size, standard error, odds ratio and interval, FDR (recomputed by Benjamini--Hochberg when absent) and Steiger columns are optional. A volcano plot of the estimate against −log10 FDR, coloured risk, protective or not significant at FDR \< 0.05, with labelled significant instruments, restrictable to the genes of one category and exportable as PNG, MHC and Steiger-directionality flags (the MHC flag is looked up by gene from the evidence table\'s MHC column and is absent when that table lacks it; Steiger-failing rows are highlighted and counted), per-category tables with CSV export, and CSV and XLSX exports of the instrument table are provided. ArthOChat is involved in two ways. A button on the upload panel sends a prompt asking it to suggest candidate exposure and outcome GWAS datasets for a trait typed by the user, searching the GWAS Catalog, OpenGWAS and PubMed; the assistant does not fetch summary statistics or run MR, and any such analysis must be run externally and uploaded. Separately, the loaded instrument table and category tables, like the integration summary and the convergence table, are exposed to ArthOChat through the scoped session context; no dedicated narrative-summary hand-off exists.

Despite its name, Cross-Omics MR computes no Mendelian randomization itself. The sub-module contains no instrument selection, no exposure--outcome harmonisation, no Wald-ratio computation and no MR-Egger or IVW estimation; it is a loader and evidence-classifier for an MR table produced by an external, unreviewed pipeline, and its own interface says so throughout, including that single-instrument genes cannot be heterogeneity-tested and that the module does not run that test even for multi-instrument genes. The ArthOChat suggestion button on the upload panel does not run a live MR or differential-expression analysis either; it only prompts the assistant to search the GWAS Catalog, OpenGWAS and PubMed for candidate accessions, and the generated prompt states explicitly that any dataset found would still need to be run through MR externally before upload. This naming is a risk in isolation: the transcriptomics and methylomics verticals each contain a genuinely live Mendelian randomization module, with harmonisation, LD clumping, Wald-ratio/IVW/Egger estimation and heterogeneity testing via TwoSampleMR and MendelianRandomization, so a reader encountering "Cross-Omics MR" beside those tabs could reasonably mistake it for another live computation rather than a convergence-evidence viewer over a precomputed file.

**2.7 Multi-omics module**

Where the Cross-Omics vertical correlates two independently computed result sets, the Multi-Omics vertical models matched, sample-level transcriptomic and methylomic data jointly to find coordinated signatures that neither layer reveals alone (Xiao & Ma, 2026). It comprises a Dataset Workspace tab and eight analysis sub-modules. Each sub-module reads the shared active dataset and can be run on its own, but they are chained by four hand-offs into one pipeline: the Dataset Workspace activates the matched layers; Cohort Harmonisation publishes the readiness tier, the identifier audit and the classification of the metadata columns, which Integration, Biomarker Discovery and SNF Clustering display in their data panels and use to preselect the outcome variable; the Integration tab publishes its fused similarity network, which SNF Clustering can partition and stress-test without rebuilding it; Biomarker Discovery and SNF Clustering supply candidate features to Gene--CpG Mapping, whose table feeds the Pathways candidate pool and is the sole input of the Biomarker Card. A pipeline strip in every sub-module\'s banner shows which of the eight stages has produced a result in the session. Every analysis sub-module offers two data routes: the active dataset built in the workspace, or a preloaded route that re-runs the analysis on one saved analysis cell of the bundled RA anti-TNF cohort (female or male × adalimumab, etanercept or drug-pooled; n = 10 to 56). That preloaded input is the 50-gene and 100-CpG subset that the original pipeline\'s DIABLO model had already selected and scaled, with treatment response as the only metadata column; it is not the cohort\'s full matrices, and results obtained on it are re-computed fits, not the pipeline\'s published numbers.

**Dataset Workspace** accepts up to eight omics blocks as CSV, TSV, TXT, XLSX or RDS in the upload route, a sample-metadata sheet and an optional sample-identifier mapping file, or fetches a GEO series (Davis & Meltzer, 2007), splitting a SuperSeries into one expression and one methylation sub-series, or loads the bundled cohort. Wide and long (tidy) tables are read, and matrices are stored as samples × features; the orientation is set by the user, with an automatic suggestion that only fires for tables whose first column does not look like an identifier. Eight omics types can be declared (RNA-seq, proteomics, methylation, metabolomics, miRNA, genomics, microbiome, other); the declaration selects the normalisation options and is recorded with the layer, but structural checks are applied only to RNA-seq and methylation blocks. Its tabs are Preview and Validate, Sample Matching with three identifier-matching strategies (exact identifier with whitespace and case normalisation, a patient-identifier column of the metadata sheet, or a user mapping file; the matched set is the name-based intersection of unambiguous identifiers, so blocks supplied in different sample orders are aligned by name rather than by position). Because the Multi-Omics vertical models the same individuals across layers, a same-patient check is applied to the matched identifiers before Preprocessing and before Activation: every layer must carry exactly the same set of patient identifiers, compared as a set rather than by row order. Any identifier present in only one layer, any blank, missing or duplicated identifier, and any sample that cannot be assigned a patient identifier through the metadata or mapping route stops the workflow with the message "Patient ID should be same, this requires expression and methylation data to be from the same patient ID, you can explore cross-omics if your Patient ID are different." (or a duplicate- or missing-identifier variant of it); the datasets are never silently reduced to their intersection, and users whose expression and methylation data come from different patients are directed to the Cross-Omics vertical, which needs no paired samples (Section 1.5), Preprocessing (per block and on the matched samples only: missing-value handling by mean, median or complete-case removal; a normalisation chosen from the type-specific list, defaulting to log2(x + 1) for count-type blocks and to unchanged beta values for methylation; an optional top-N variance filter; and an unconditional per-feature z-score), Batch Diagnostics with the same batch-by-phenotype confounding block as the transcriptomics module and an optional ComBat or limma batch correction that replaces one block and does not include the phenotype as a protected covariate, and Compatibility and Activate, which assigns each layer a compatibility status from its validation, missingness, duplicate identifiers, zero-variance features and cross-layer overlap, and blocks activation of layers marked not compatible and, whenever the same-patient check fails, of the whole dataset. Activating a dataset writes a record to the session-wide Analysis records log (Section 2.2) with the intake source, the matching method, the same-patient check, the per-block normalisation and feature filter, the missing-value handling and any batch correction; every other Multi-Omics sub-module writes its own record when it produces a result (Cohort Harmonisation, the DIABLO, SNF and sex-stratified runs of the Integration tab, SNF Clustering, Biomarker Discovery with its hold-out and external validation, Gene--CpG Mapping, Pathways and MOFA), each with a checksum of its input, the parameters actually used, the seed and the package versions, so the whole vertical is covered by the same downloadable log as the transcriptomics vertical.

**Cohort Harmonisation** is a diagnostic report on the active dataset that later stages read. It classifies clinical and demographic columns, computes pairwise sample overlap between layers, labels every identifier as exact match, normalised match, unmatched, duplicate or ambiguous, enumerates the feasible modality subsets with the number of matched samples in each, and assigns integration-readiness tiers (Han, Kwon & Jung, 2025) (Ready at ten or more matched samples, Limited at three to nine). It does not rewrite identifiers, and each analysis sub-module still recomputes the matched-sample intersection itself (after the same-patient check the intersection is the whole cohort, so the two agree), but the report is now consumed downstream: it publishes the readiness tier of the all-modality cell, the matched identifiers, the count of unmatched, duplicate or ambiguous identifiers and the columns classified as phenotype or batch candidates, and the Integration, Biomarker Discovery and SNF Clustering panels display that tier, warn when their own matched count differs from the harmonised one, and default their outcome selector to the first classified phenotype column. When the report has not been run, those panels say so and ask for it.

**Integration (DIABLO and SNF)** runs two complementary methods. DIABLO (Singh et al., 2019; mixOmics, Rohart et al., 2017) is supervised: a block sparse partial least squares discriminant analysis with a user-set design matrix (default 0.1), a number of components that is, by default, chosen by perf on a non-sparse block.plsda fitted over the feasible range (one to five, bounded by the class count and the smallest class), taking choice.ncomp on the weighted-vote balanced error rate with at least three repeats and falling back to the balanced-error-rate minimum when perf returns no choice, or set by the user; and a user-set number of features retained per block and component (default 20 and 10). Grid tuning of the feature count by tune.block.splsda on balanced error rate is available as an option and is off by default because of its running time; when it is on, the final model uses the counts tuned on the whole data set, but the reported error rates and AUROC come from a nested loop in which the grid search is repeated inside every outer training fold, so the reported performance does not benefit from a feature-count choice that saw the held-out samples. The component number chosen by perf on the whole data set is not re-tuned inside that outer loop. Performance is estimated by perf with repeated stratified M-fold or leave-one-out cross-validation (folds bounded by the smallest class, three to ten repeats by sample size), which refits the model in every fold with the chosen feature counts and reports balanced and overall error rate, per-class error and per-feature selection frequency; the prediction distance is chosen as the one with the lowest cross-validated balanced error rate. The AUROC shown beside these error rates is not the AUC that perf returns: in the installed mixOmics (6.37.0) that value is not a held-out estimate (on two blocks of pure Gaussian noise, n = 50, it reports an AUC of 1.00 while the balanced error rate is 0.52), so the application computes its own out-of-fold AUROC by refitting the block model in every fold of a repeated stratified split, scoring each held-out sample with the weighted prediction for the positive class, averaging the scores over repeats and reporting one ROC with a DeLong 95 % confidence interval (0.43 on the same noise). Whether this behaviour of perf is specific to the installed version or is documented upstream was not established; the application simply never displays that number. With manual feature counts the estimate is a repeated cross-validation conditional on those counts; with grid tuning on it is nested with respect to the feature counts, and only the component number and the prediction-distance choice remain whole-data decisions. A feature-count list shorter than the number of components is completed by repeating its last value and capped at the block width, so every component is sparse and the \"selected features\" table lists only selected features (mixOmics would otherwise fill the missing entries with all features). Similarity network fusion (Wang et al., 2014; SNFtool) is unsupervised: a sample-similarity network is built per layer from z-scored features with the SNFtool scaled exponential kernel (K nearest neighbours near √n + 5, bounded to the recommended 10--30; scaling parameter 0.5; the kernel is fed the Euclidean distance, the square root of the squared distance that dist2 returns, as in the SNFtool documentation) and the networks are fused iteratively into one network (20 iterations by default, or until successive fused networks correlate above 0.995) capturing shared and layer-specific structure (Chierici et al., 2020); three clustering methods are offered on the fused network (spectral, average-linkage hierarchical and PAM), with the cluster count entered by the user (default two) or, optionally, estimated from the eigengap. Optional grid tuning of K and the scaling parameter scores each candidate by the silhouette of the resulting clustering on the fused network itself. A post-hoc panel reports how the clusters line up with the selected outcome by Fisher\'s exact test, normalised mutual information and the adjusted Rand index (Hubert & Arabie, 1985). A Compare tab sets each method against single-omics baselines rather than against the other: for DIABLO it fits an elastic-net classifier per layer with a nested cross-validation (in-fold variance filtering and scaling, inner cross-validated penalty selection) and tabulates the per-layer AUROC beside DIABLO\'s cross-validated AUC; for SNF it clusters each layer\'s own network at the fused cluster count and reports normalised mutual information and the adjusted Rand index against the fused clustering. DIABLO and SNF groupings are not compared with each other. The supervised comparison plots the chance reference at an AUROC of 0.5 and reports the cohort\'s majority-class proportion separately, as an accuracy, in the accompanying note. A Sex-Stratified tab (shared with Biomarker Discovery) is described under that sub-module.

**MOFA** applies Multi-Omics Factor Analysis (Argelaguet et al., 2018; MOFA2, Argelaguet et al., 2020) to the activated workspace as an optional, unsupervised exploration before phenotype-driven modelling. Views are passed as features × samples matrices on the matched samples with a Gaussian likelihood for every view, the number of factors (default ten, capped at n − 1), the seed and the convergence mode being the only user-set options. It reports variance explained per factor per view from get_variance_explained, factor scores and weights, and a cross-omics correlation tab that is independent of the factor model: it correlates the top-variance features of two layers pairwise across samples with Benjamini--Hochberg correction within that subset. MOFA2 runs through an external Python installation of mofapy2 located by reticulate (the RETICULATE_PYTHON variable first, then python3 on the path); the Dockerfile installs Python 3 with mofapy2 0.7.5 and sets that variable, so the sub-module is available in the container. The container was not rebuilt on the development machine (no Docker daemon is available there), so this statement rests on the Dockerfile as written, not on a tested image. No precomputed MOFA fit is shipped for the bundled cohort; a live fit can be trained on the activated preloaded blocks, but that input is the 150-feature subset described above.

**SNF Clustering** offers three data routes. From the active dataset it runs similarity network fusion on the selected blocks with its own per-block preprocessing (missing-value handling, an optional log2, M-value or autoscale transform, and an optional top-N variance or MAD filter) and the same K, scaling, iteration and cluster-count controls as the Integration tab. From the Integration tab it carries the fused network that tab published, together with the per-block networks and the blocks that built them: the network is not rebuilt, its K, scaling parameter, iteration count and standardisation are shown and locked, only the cluster count, clustering technique and seed are set here, and the resampling-stability and parameter-sensitivity checks rebuild SNF on subsamples with exactly the carried parameters, so they stress-test the network that Integration produced. The third route is the preloaded cohort. The cluster count is entered by the user (default two) or, optionally, estimated from the eigengap of the fused affinity matrix (von Luxburg, 2007), and the partition is by spectral clustering (Jiang et al., 2019), hierarchical clustering or PAM. Subgroups are stress-tested by a parameter-sensitivity check that re-runs the clustering at the low and high end of K, the scaling parameter and the iteration count and reports the adjusted Rand index against the reference clustering, and by association with clinical variables by Fisher\'s exact test with Cramér\'s V as effect size or Kruskal--Wallis, and with survival by log-rank test and Cox regression, with Benjamini--Hochberg correction across the tested variables; clinical variables never enter the clustering. A resampling-stability panel (20 draws of 80 % of samples, adjusted Rand index against the reference, a verdict of Stable at ARI ≥ 0.75; Smolkin & Ghosh, 2003) draws all 20 subsamples before any rerun, because each seeded SNF rerun resets the random-number generator; the panel reports the number of distinct subsamples actually drawn, so that the defect the audit found (one subsample repeated 20 times) would be visible if it recurred. A per-feature Kruskal--Wallis ranking of cluster-associated features (Benjamini--Hochberg) is computed on the same samples that formed the clusters and supplies the \"SNF\" candidates to Gene--CpG Mapping. With a single omics layer available, a single-omics fallback runs the same stratification on that layer without a fusion step.

**Biomarker Discovery** has two engines. The whole-cohort engine selects a cross-layer panel with DIABLO on two blocks assigned the transcriptomics and methylomics roles, after an outcome-blind variance prefilter (default 5,000 features per block), and estimates performance by (non-nested) perf cross-validation, supplemented by a pooled out-of-fold ROC curve from per-fold refits with the same parameters; selected features are reported with their selection frequency across the cross-validation refits and a three-level stability label (Stable ≥ 0.8, Moderately stable ≥ 0.5). Its default component and feature-count settings are those of the Integration tab, with the same feature-count completion rule. Two independent evaluations are available. A sealed hold-out fraction (0 to 50 %, default 0) is split off by stratified sampling before any modelling; feature selection, tuning and cross-validation run on the remaining samples only, and the hold-out is scored once with the final model (AUROC with DeLong interval, balanced error rate, confusion table). Because the preloaded input is a feature subset already selected on all samples of its analysis cell, the interface marks a hold-out drawn from it as not independent, and such a hold-out is not evidence. An External Validation tab accepts an independent cohort (expression matrix, methylation matrix and metadata sheet sharing the same patient identifiers, passed through the same-patient check), maps its outcome levels onto the discovery classes, refits the selected panel on the discovery training samples using only the panel features that the external cohort measures (Ensembl and symbol gene identifiers are reconciled through org.Hs.eg.db), standardises each cohort per feature within itself and scores the external samples with an AUROC, DeLong interval and balanced error rate; the transfer is refused when fewer than half of the panel features are measured externally, a threshold the user may lower for an exploratory check, and the coverage per block is always reported. The sex-stratified engine, run for the whole cohort and separately by sex, uses repeated stratified five-fold cross-validation (five repeats) with limma ranking inside each fold (optionally adjusted for a covariate such as drug), train-fold mean imputation, and either DIABLO (two components, one feature count per block between 5 and 15, a design weight set to the absolute correlation of the two blocks\' mean profiles) or random forest as the classifier (Thelagathoti et al., 2025; Novoloaca et al., 2024). Feature selection is therefore leakage-safe, but the feature counts, component number and tree count are fixed constants rather than tuned in an inner loop, so the procedure is cross-validation with in-fold selection rather than nested cross-validation. Both variants score each held-out sample on a continuous scale, the DIABLO variant by the weighted prediction for the positive class and the random-forest variant by the class probability, averaged over the repeats, and the AUROC is computed on that score. Each stratum reports the AUROC with a DeLong 95 % confidence interval, a flag for intervals that exclude 0.5, the features\' selection frequency across folds, and a separate full-cohort refit that provides the reported panel (component-1 loadings or Gini importance). Comparing the female and male panels shows whether the selected features depend on sex.

The External Validation transfer checks that the uploaded external cohort\'s own expression and methylation files share a common patient identifier and that the panel\'s features reach the coverage threshold, but it runs no complementary check that those external identifiers are disjoint from the discovery cohort\'s identifiers used to fit the panel: nothing compares the uploaded sample IDs against the training IDs. A user who uploaded a cohort that overlapped the discovery samples would receive a transfer result with no warning that it is not independent.

**Gene--CpG Mapping** has two routes. The default browses the bundled pipeline\'s own gene--CpG tables for the etanercept and drug-pooled panels (723 and 1,013 pair rows over 21 and 20 genes); the live route links each candidate gene (DIABLO-selected features, SNF cluster-associated features, or user-entered identifiers) to its CpGs by promoter or gene-body annotation from the Illumina 450K or EPIC manifest, taking the first gene and region listed for each probe, correlates expression and methylation per pair across the matched samples (Pearson or Spearman, Benjamini--Hochberg across pairs), and classifies direction (hypo- or hypermethylation with up- or downregulation) from per-gene and per-CpG Welch t-tests between the two levels of a chosen design column, the CpG test being on M-values, with the differential-methylation threshold expressed as \|ΔM\|. In the live route these tests are run on the candidate subset, on the same samples and outcome that selected the candidates, so their significance flags are descriptive rather than confirmatory; genome-wide p-values and FDR over all features are stored alongside. A canonical label marks inverse promoter pairs and concordant gene-body pairs, and one covariate-adjusted linear model is fitted for the top-ranked pair. A priority score is computed as a weighted composite of within-table-normalised effect sizes, the smaller of the two FDRs, the pair correlation, the canonical label and the DIABLO and SNF provenance flags (the \"joint\" flag, which duplicates the DIABLO flag, is not scored). The label attached to a pair does not use the word biomarker: a pair is a \"Supported multi-omics pair\" only when it is significant in both layers with the canonical direction, a \"Prioritised candidate pair\" when its score is 60 or above without that support, and a \"Candidate pair\" otherwise. With the default thresholds no pair in either bundled table is supported, because no CpG in those tables reaches a methylation FDR below 0.05. Enhancer annotation and TSS distance are not implemented and are reported as not available.

**Pathways** offers seven gene-set collections (GO Biological Process, Molecular Function and Cellular Component, KEGG, Reactome, WikiPathways and MSigDB Hallmark) through clusterProfiler, ReactomePA and msigdbr, two methods, over-representation (hypergeometric, Benjamini--Hochberg within each collection) and GSEA (fgsea multilevel), applied, by default, in two parts: gene-identifier candidates are tested with the hypergeometric test, and CpG candidates are tested separately with missMethyl\'s gometh (Phipson, Maksimovic & Oshlack, 2016), which models the number of array probes per gene and probes annotated to several genes, on the 450K or EPIC manifest chosen by the user, against the measured CpGs of the active methylation layer when one exists and otherwise against all array probes; gometh covers GO and KEGG only, so for the other collections CpG candidates are not tested. With the correction switched off the previous behaviour applies, a single joint gene list formed by the union of expression features and the first-listed gene of each candidate CpG, and the metadata table then records that the probe-number bias was not corrected; a third option labelled \"Reactome topology\" is Reactome over-representation with a per-term child-event count retrieved from the Reactome web service, not a topology-based method. The gene list comes from the in-session candidate pool or from an uploaded table whose columns are detected and confirmed by the user; uploaded p-values are not used for selection. Three background definitions are offered: the active dataset\'s features, the whole annotation, and the bundled cohort\'s 21-gene candidate list (flagged as unsuitable); the option to use the uploaded identifier list as its own background, which the audit found to be identical to the tested list, has been removed. Each enriched term is annotated post hoc with the contributing expression and methylation features, which is possible only for the collections that return gene symbols (GO and Reactome over-representation), and rendered KEGG maps through pathview (Luo & Brouwer, 2013); KEGG queries, pathview maps and Reactome diagrams require internet access.

**Biomarker Card (multi-omics)** presents one Gene--CpG Mapping pair at a time in eight sub-tabs (overview, status, dataset, expression, methylation, integrated evidence, patient-level values and download). It is read-only over the Gene--CpG Mapping table and the cross-omics evidence classifier, and assigns a tier on a ladder from Insufficient through Expression-only, Methylation-only, Moderate and Discordant to Strong, where Strong additionally requires a negative pair correlation at FDR \< 0.05 and is therefore unreachable on the bundled route, which carries no sample-level correlations. The DIABLO and SNF marks on the card are the provenance flags carried in the mapping row; the card does not read the Integration, SNF Clustering, MOFA or Pathways results. The patient-level tab reads the active layers directly and requires layers named \"Transcriptomics\" and \"Methylomics\" with gene-symbol identifiers.

**2.8 ArthOChat**

ArthOChat is the assistant embedded in every vertical, implemented with the ellmer and shinychat packages (Wickham, 2025) in a slide-out drawer. It selects a backend at start-up: when an Anthropic API key is configured, as in the public deployment, it uses the hosted Claude Sonnet 5 model (Anthropic, 2026), because a public application cannot depend on a model running on the user\'s machine; without a key, as in local development, it falls back to the Qwen3 8B model (Yang et al., 2025) served locally by Ollama, which runs offline and incurs no API cost.

Both backends run at temperature 0, and the Ollama backend additionally uses a fixed seed (20260904), because testing showed that at the default temperature the same unanswerable question could return two different fabricated answers on retry; deterministic sampling removed this. The assistant is given the same system instructions and the same eight tools regardless of backend: PubMed search, transcriptomics and methylomics methodology look-up, GWAS Catalog search, look-up of another sub-module\'s context, a tool that proposes a differential-expression run, one that executes it after the user confirms (at most five executions per session), and one that cancels a pending action. The assistant can therefore run a DGE analysis on the user\'s behalf, but only after explicit confirmation.

Two grounding mechanisms limit fabrication. The system prompt is rebuilt per sub-module with the live results of that sub-module, and any sub-module not yet run is marked \"NOT YET RUN IN THIS SESSION\" so that the model cannot describe results that do not exist. After each reply, a detector scans for citations not present in the retrieved PubMed results and flags them as ungrounded. Context is scoped to the current sub-module and the chat resets on navigation, with a cap of 40 turns. A verification protocol with recorded question sets and result tables is kept under tests/arthochat_verification/. **\[AUTHOR: report the verification results (number of questions, fabrication rate before and after temperature 0) in Section 3.\]**

The curated biomarker panels built from these regions (`biomarker_panel_female.csv`, `biomarker_panel_male.csv`; a CpG is included if it is DMP-significant, among the top 50 DMRs by significance, or both) list 810 CpGs across 84 unique genes for women (17 tagged `DMP_significant`, 1 `DMP_significant+DMR_top50`, 792 `DMR_top50`) and 724 CpGs across 63 unique genes for men (all `DMR_top50`, since no male CpG was DMP-significant). As already disclosed in Section 2.5.6, feeding a from-scratch regeneration's own DMP statistics into the same DMRcate pipeline recovers 64.2 % of the shown female regions and 62.9 % of the shown male regions by genomic overlap (57.1 % / 57.2 % of the FDR &lt; 0.05 ones), so the DMR counts above are a partial, not exact, reproduction of the shipped table.

**Sex-interaction model.** Unlike DMP and DMR, the group-by-sex interaction sub-module (Section 2.5.7) has no precomputed route at all: it runs live on the active dataset, including the bundled matrix, so there are no precomputed interaction-model hit counts to report for this case study. This is a structural property of that sub-module, not a gap in the bundled data.

**Co-methylation network (WGCNA).** The shipped module assignment tables (`tables/script05_wgcna_sexstratified/module_assignment_{female,male}.csv`), built on the top 20,000 most variable CpGs by MAD with a signed, Pearson-correlation network (Section 2.5.8), place the 20,000 CpGs into 18 real modules plus the unassigned grey module in women (19 labels total) and 36 real modules plus grey in men (37 labels total). Correlating each module eigengene with RA status (`module_trait_{female,male}.csv`, Pearson r with Benjamini-Hochberg FDR) finds 17 of the 18 real female modules significant at FDR &lt; 0.05 (led by turquoise, r = 0.302, FDR = 1.6 × 10⁻¹⁰, 8,030 CpGs) against 0 of the 36 real male modules (the strongest male module, green, reaches only FDR = 0.072). As already disclosed in Section 2.5.8 and the reproducibility check, a from-scratch WGCNA regeneration on the same parameters converges on a different module count (27 in both sexes, against the 18/36 real modules shown here) with Adjusted Rand Index 0.573 (female) / 0.831 (male) against this shipped assignment, so the module count and the trait-association counts above describe this specific shipped run, not a reproduced network.

**Candidate CpGs.** The Candidate CpGs sub-module (Section 2.5.9) has no dedicated precomputed output table of its own: on the bundled route it recomputes a genomic-range overlap between the WGCNA module assignments and the DMR table above, live, every time the tab is opened, filtered by the module and DMR settings the user chooses (module significance, minimum \|kME\|, DMR FDR ≤ 0.05, minimum \|Δβ\|, and so on). Because the result therefore depends on filter choices made at run time rather than on a single fixed output, no single "number of candidate CpGs" is bundled to report here. **\[AUTHOR: run Candidate CpGs live on the bundled cohort at a stated filter setting (e.g. default thresholds) if a specific count is wanted for this case study.\]**

**mQTL Mendelian randomisation and colocalisation.** The bundled MR route (Section 2.5.10) carries a pre-built, pre-clumped GoDMC cis-mQTL instrument set against the Ishigaki et al. (2022) European RA GWAS (GCST90132223) for 8 CpGs in total (`instrument_counts.csv`: 1-2 instruments each), and TwoSampleMR is then run live on that cached set. 6 CpGs are estimable in the female stratum (one by inverse-variance weighting on 2 instruments, five by Wald ratio on a single instrument each) and 2 in the male stratum (one IVW on 2 instruments, one Wald ratio); none reaches even nominal p &lt; 0.05 in either sex (female p range 0.40-0.98; male p = 0.74 and 0.27), so 0 of 6 female and 0 of 2 male CpG-level MR estimates are significant. Colocalisation (Section 2.5.11) tests 7 of these 8 CpGs against the same GWAS with coloc.abf at the pipeline's own posterior threshold of 0.8 (`coloc_results.csv`; the eighth CpG, the male-only cg23881902, is not tested, consistent with the module's stated ≥ 10-shared-SNP requirement for a coloc run); every one of the 7 returns an "inconclusive" verdict, with PP.H4 (shared causal variant) ranging only 0.008-0.045 and PP.H1 (association with methylation only) dominating every region at 0.94-0.99. No CpG in this case study therefore carries supported MR or colocalisation evidence at the application's own thresholds.

**ML feature selection.** Run separately by sex on the SVA-adjusted panel (Section 2.5.12), the univariate/penalised/tree-based/RFE ensemble selects, by method, 6 CpGs (LASSO), 37 (Boruta) and 40 (SVM-RFE) in women, and 1 (LASSO), 27 (Boruta) and 25 (SVM-RFE) in men (`feature_selection_summary_{female,male}.csv`). Agreement across all three methods simultaneously is rare (1 CpG in women, cg21740204; 0 in men), but the looser ≥ 2-of-3-method consensus used elsewhere in the pipeline (`ensemble_votes_{female,male}.csv`, column `n_votes` ≥ 2) yields 12 CpGs in women and 9 in men, with no CpG shared between the two sex-specific panels (0 of 21 union). These are exactly the 12-female/9-male, 21-CpG-union panels that Section 2.5.13 describes as the bundled Diagnostic Classifier's feature source.

**Diagnostic classifier and external validation.** The Diagnostic Classifier's bundled route fits six algorithms (random forest, SVM, k-NN, elastic-net logistic regression, XGBoost and a shallow neural network) on the cell-type-adjusted, 12-CpG female and 9-CpG male panels above, with a 75 % stratified training split (`tables/script09_diagnostic_classifier/tables/diagnostic_panel_auc_{female,male}.csv`). In women, internal-test AUC ranges from 0.626 (logistic regression) to 0.684 (random forest, 95 % CI 0.586-0.781), while training AUC reaches 1.00 for random forest, indicating substantial overfitting relative to the internal-test figure. In men, internal-test AUC ranges from 0.650 (neural network) to 0.743 (SVM, 95 % CI 0.598-0.887); no male external-test AUC exists because the bundled external cohort contains no male samples (below). External validation (Section 2.5.14) uses GSE111942 (Zhu et al., 2019), 43 PBMC samples on the Illumina 450K array, 25 RA cases and 18 controls, all female (`tables/script09_diagnostic_classifier/tables/gse111942_external_pheno.csv`); because it contains no men, only the female panel's external-test AUC is reported, and it varies widely by algorithm: 0.791 (random forest, 95 % CI 0.658-0.925) and 0.707 (k-NN) exceed the corresponding internal-test estimate, while 0.676 (SVM), 0.544 (neural network), 0.479 (XGBoost) and 0.189 (logistic regression, i.e. worse than chance on this external cohort) do not. No single algorithm is uniformly best across the training, internal-test and external-test columns, and the wide spread of the external-test AUCs (0.189-0.791) across six algorithms fitted to the same 12-CpG panel indicates the external transfer is unstable rather than confirmatory for this case study.

**3.3 Cross-omics and multi-omics integration**

- Genes per evidence tier from cx_classify_evidence(); convergence with eQTL-MR and mQTL-MR.

The multi-omics results below were produced with the application\'s own engines after the corrections described in Section 2.7 (out-of-fold AUROC, sparse components on every run, distinct resampling subsamples, chance reference at 0.5, Euclidean-distance SNF kernel). Every number is a held-out or out-of-fold estimate unless stated otherwise; none is a training-set figure. All runs used seed 1.

**Bundled RA anti-TNF cohort (Tao et al., 2021; GSE138747).** The bundled tables carry the original pipeline\'s nested cross-validated, out-of-fold AUROCs for the six analysis cells, and they are the only bundled figures that are not circular (the preloaded feature subsets were selected on all samples of each cell, so any model re-fitted on them in the application reproduces near-perfect but uninformative performance: cross-validated balanced error rates of 0.00 to 0.18 and a sealed hold-out AUROC of 1.00 on the female drug-pooled cell). The pipeline\'s DIABLO AUROCs were 0.40 (95 % CI 0.22--0.59, n = 27) for female adalimumab, 0.30 (0.00--0.61, n = 10) for male adalimumab, 0.50 (0.32--0.67, n = 29) for female etanercept, 0.67 (0.46--0.87, n = 13) for male etanercept, 0.47 (0.31--0.62, n = 56) for the female drug-pooled cell and 0.52 (0.27--0.77, n = 23) for the male drug-pooled cell; no interval excludes 0.5. The pipeline\'s random-forest counterparts were 0.31, 0.14, 0.67 and 0.81 (0.56--1.00, n = 13) for the same four drug-by-sex cells, the last being the only multi-omics interval above 0.5 in the bundled cohort, and the single-omics random forests ranged from 0.26 to 0.50. The response-informed SNF variant reached 0.63 (0.42--0.84) in female and 0.62 (0.28--0.96) in male etanercept patients. The pipeline\'s own benchmark table records an integrated-model accuracy of 0.41 (female) and 0.57 (male) against the 0.79--0.89 reported by Tao et al. for their per-drug single-omics classifiers, so the sex-stratified multi-omics re-analysis does not reproduce the published accuracy. Gene--CpG Mapping finds no supported pair in either bundled table (0 of 723 etanercept and 0 of 1,013 drug-pooled pairs are significant in both layers at FDR \< 0.05).

**Independent cohort (Spreafico et al., 2016; GSE89253).** To obtain an evaluation that does not depend on the bundled cohort, the matched CD4+ T-cell expression (GSE89252, Illumina HT-12, 15,209 genes) and DNA-methylation (GSE89251, Illumina 450K, 339,281 CpGs as deposited, M-values) profiles of juvenile idiopathic arthritis patients in anti-TNF-induced remission were retrieved from GEO and passed through the Multi-Omics workflow. The baseline (T0) samples of the patients who later flared after anti-TNF withdrawal or maintained inactive disease were used (n = 50: 23 flare, 27 inactive disease; 37 female, 13 male); the 12 patients in the intermediate \"NO ID\" group were excluded. The analogy drawn here, that failure to maintain remission after anti-TNF withdrawal in JIA corresponds to non-response to anti-TNF in RA, is an assumption of this thesis and not a claim of the original study; the two cohorts differ in disease, tissue (PBMC versus purified CD4+ T cells), platform and outcome definition.

*Transfer of the RA panels.* The six RA DIABLO panels (two components, 15 features per block and component, refitted on each cell\'s samples) were applied to the 50 baseline JIA samples with the External Validation tab\'s procedure. Between 21 % and 43 % of the panel features are measured in the JIA cohort (4--14 of 24--29 genes after Ensembl-to-symbol mapping, 4--13 of 29--30 CpGs), below the 50 % coverage the tab requires, so under the default setting none of the panels is evaluable in this cohort. With the guard lowered to 20 % for an exploratory check, the AUROCs for predicting flare were 0.43 (0.26--0.60), 0.68 (0.53--0.84), 0.58 (0.41--0.75), 0.63 (0.47--0.79), 0.47 (0.31--0.64) and 0.51 (0.34--0.67) for the female adalimumab, male adalimumab, female etanercept, male etanercept, female drug-pooled and male drug-pooled panels. One interval, that of the male adalimumab panel, lies above 0.5, but it rests on 12 measured features out of 56 (21 % coverage), a training cell of 10 patients, and six panels tested without correction, and it is not interpreted as replication.

*Discovery on the JIA cohort with a sealed hold-out.* Run as a user would run an uploaded cohort, with the 5,000 most variable genes and CpGs, the component number set manually to two, 20 and 10 features per block and component set manually (so the reported figures are repeated, not nested, cross-validation), a 25 % stratified hold-out (39 training, 11 sealed samples) and 5-fold cross-validation repeated 10 times, the whole-cohort DIABLO engine did not predict flare: cross-validated balanced error rate 0.59, out-of-fold AUROC 0.35, per-layer elastic-net baselines 0.45 (expression) and 0.40 (methylation), and a sealed hold-out AUROC of 0.53 (0.14--0.93; 6 of 11 samples correctly voted, balanced error rate 0.45). The sex-stratified engine, which ranks features by limma inside every fold and retains 50 genes and 100 CpGs, gave a pooled AUROC of 0.61 (0.45--0.77) with DIABLO and 0.60 (0.43--0.76) with random forest; in the 37 female patients 0.64 (0.45--0.83) and 0.56 (0.37--0.75); in the 13 male patients the estimates were 0.31 (0.00--0.63) and 0.05 (0.00--0.16), the latter interval lying entirely below 0.5, which with 6 flares and 7 remissions is read as instability rather than a reversed signal. No multi-omics estimate on this cohort excludes chance. Unsupervised SNF on the same two blocks (Euclidean-distance kernel, K and scaling at their defaults, two clusters, spectral) produced two clusters of 28 and 22 baseline samples with a resampling stability of ARI 0.73 (SD 0.22 over 20 distinct subsamples, \"Moderately stable\") and no association with later flare (14/14 versus 13/9 inactive/flare; Fisher p = 0.58, Cramér\'s V = 0.05).

*Corrected stability panel on the bundled cells.* On the preloaded female and male etanercept cells the repaired resampling panel reports ARI 0.98 (SD 0.05) and 1.00 (SD 0.00) over 20 distinct subsamples, and the two SNF clusters coincide with treatment response (Fisher p = 1.5 × 10⁻⁸ and 5.8 × 10⁻⁴). These figures are shown to demonstrate that the panel now resamples, not as evidence: the preloaded blocks are the features that the original pipeline\'s DIABLO model selected for response on these same patients.

*Summary.* Across both cohorts the multi-omics vertical yields no supported gene--CpG pair, no panel whose out-of-fold or held-out AUROC interval excludes chance in a valid evaluation, and no RA panel that can be evaluated at the default coverage in the one independent matched cohort available. The application\'s contribution in this section is therefore that every one of these null results is a trustworthy number, obtained with a sealed hold-out, an external-cohort transfer and out-of-fold estimates that the interface now enforces; it is not a positive biomarker finding.

**3.4 ArthOChat verification**

**4. Discussion**

**\[AUTHOR: write in prose; the bullets are the points an examiner will expect.\]**

**4.1 Comparison with existing tools**

- Return to Table 1. ArthOMix is the only reviewed tool to stratify by sex, to run methylomics from IDAT to validated classifier, to attach MR and colocalisation to both layers, and to offer both cross-omics and multi-omics integration with three isolated intake paths.

- Nearest competitors: Omics BioAnalytics (Dyce et al., 2025), Holomics (Munk et al., 2024), xOmicsShiny (Gao et al., 2025), OmNI (Potter et al., 2026). State what each does that ArthOMix does not (for example proteomics and metabolomics layers).

**4.2 Statistical safeguards**

- Batch-by-phenotype confounding block, with the batch × group table and the unbalanced-design caveat of Nygaard, Rødland & Hovig (2016) shown before every correction; held-out split before the feature-selection step (candidate genes are still chosen on the full pool, which is why the nested estimate is the headline); an optional sealed validation hold-out reserved on the Dataset tab before any analysis, which removes that caveat and is scored only with frozen models; leakage-safe nested cross-validation as the headline metric; study-wise meta-analysis as an alternative to merging; interaction models beside stratified analyses; bacon inflation control; untestable-versus-failed distinction in cross-ancestry MR replication; a session-wide analysis-record log for every transcriptomics run; and a strict vocabulary in which \"replication\" (cross-tissue, cross-ancestry) is kept distinct from \"validation\", which is reserved for the frozen-model External Validation tab.

**4.3 Limitations**

- Genome build hg19 only; 450K and EPIC manifests only (no EPICv2 DMR calling).

- No enhancer annotation or TSS distance in Gene--CpG Mapping.

- Bundled MR, colocalisation and candidate-CpG routes are cached look-ups, not live recomputation.

- No cancellation of a running job.

- The transcriptomics Biomarker Card\'s \"Strong candidate\" tier depends on the External Validation tab having been run in the same session for a panel containing the gene; it is not reached from bundled or precomputed results.

- Cross-reactive and MAF probe filters need a user-supplied list; none is bundled.

- The session-wide analysis-record log covers the transcriptomics, multi-omics <span style="color:purple">and (as of 2026-09-08) cross-omics verticals</span>; in the methylomics vertical a provenance manifest is written by DMP alone<span style="color:purple">, the only sub-module of that vertical this pass checked for it</span>.

- <span style="color:purple">Of the Methylomics vertical's precomputed tables, QC, DMP, DMR and WGCNA have been checked for regeneration from the bundled raw matrix (2026-09-08): the QC sex-mismatch check cannot be reproduced from what is bundled at all (the raw matrix already excludes sex-chromosome probes) and its PCA outlier flag does not reproduce numerically; DMP reproduces closely at the statistic level (r ≥ 0.95) but not in its small significant-CpG counts; DMR recovers 57-65 % of the shown regions by overlap; WGCNA module assignment reproduces with Adjusted Rand Index 0.57 (female) / 0.83 (male). ML Feature Selection was also attempted and is a weaker, honest negative (LASSO selection-frequency correlation r = 0.05-0.20): unlike the four stages above, this module has no `preloaded`-mode hyperparameter defaults encoded in the live application, so there is no code evidence the generic defaults tested match the original pipeline's methodology - a structural, not incidental, gap. The Diagnostic Classifier and every precomputed table in Transcriptomics and Cross-Omics remain unchecked for the same structural reason or for lack of time.</span>
- <span style="color:purple">The Multi-Omics GEO-fetch path was extended (2026-09-08) to accept two independently-specified accessions (`multi_geo_dual_fetch()`) for studies without a SuperSeries wrapper, with per-sample title-derived patient-ID matching fed into the existing Sample Matching tab. A first attempt to apply this to the bundled cohort's own source data initially and incorrectly concluded GSE138746/GSE138653 were such an unlinked pair; re-tested against the correct SuperSeries accession, GSE138747, GEO's own relation metadata resolves the linkage correctly through the application's pre-existing, unmodified `multi_geo_autosplit_fetch()` - the sole, permanent reason live fetch fails for this cohort is that GEO stores no values at all for RNA-seq series matrices (confirmed directly), a format limitation with no bundled or fetchable fix, not a linkage problem. Using sex labels recovered from GEO sample titles (verified 100 % against the bundled patient metadata) and freshly-fetched raw data, an independent, non-circular re-analysis was run across 14 scenarios spanning the app's own drug × sex × engine benchmark space (`reproduce/multiomics/02_all_arms.R`, `03_snf_only.R`): 12/12 nested-cross-validated arms and 2/2 SNF clustering tests show no interval excluding chance, corroborating Section 3.3's finding from raw data through a different code path and a far wider scenario sweep than the single bundled-cohort re-analysis reported there.</span>

- The bundled transcriptomics cohort is the normalised, batch-corrected training partition; the sealed hold-out and frozen preprocessing parameters of the case study are not shipped, so the case-study figures of Section 3.1 are not regenerable inside the application (Section 2.4.1).

- The bundled cohort\'s batches are unbalanced with respect to diagnosis (for example 32 RA versus 7 controls in one GSE93272 batch), so differential-expression counts on the merged, ComBat-corrected matrix should be read as a sensitivity result beside the study-wise meta-analysis (Nygaard, Rødland & Hovig, 2016).

- The bundled male stratum (17 RA, 21 controls) is below the sample size at which a multivariable panel is stable; every male-stratum classifier result is labelled exploratory in the application and should be read as such here.

- Age is missing for 111 of the 183 bundled samples, so age cannot be used as a covariate in the case study.

- A sealed hold-out reserved on the bundled cohort still shares the quantile-normalisation and ComBat parameters of the archived pipeline, because the bundled matrix is already corrected on all 183 samples; and a hold-out reserved on any cohort that is later re-normalised or batch-corrected in the application is processed together with the discovery samples before being re-sealed. Frozen-parameter projection onto the reserved samples is not implemented (Section 4.4).

- GSE15573 is used only by the Diagnostic Model\'s External Validation tab; it is small (33 samples, 9 male), so male-panel external estimates on it are exploratory, and it is not part of any bundled fast path.

- No precomputed MOFA fit exists for the bundled cohort, and the preloaded route of every Multi-Omics sub-module re-computes on a 150-feature, pre-scaled subset of one analysis cell rather than on the full matrices. MOFA2 depends on an external Python installation with mofapy2, which the Dockerfile now installs; the resulting image has not been built and tested by the author.

- Four Multi-Omics outputs that the audit found numerically invalid have been corrected and are now reported: the SNF resampling-stability verdict draws distinct subsamples, the Compare tab\'s chance reference is 0.5, the pathway \"uploaded background\" option has been removed, and a short DIABLO feature-count list no longer leaves the final component non-sparse. A fifth defect found during the correction, that the AUC returned by mixOmics perf is not a held-out estimate in the installed version, is handled by never displaying that number and reporting an out-of-fold AUROC instead.

- The biological evidence of the Multi-Omics vertical is null. No gene--CpG pair is supported in the bundled tables, no multi-omics panel\'s out-of-fold or held-out AUROC interval excludes 0.5 in a valid evaluation on either the bundled RA cohort or the independent JIA cohort, and the RA panels cannot be evaluated at the default feature coverage in that cohort because fewer than half of their features are measured on its platforms. The only independent matched cohort used differs from the bundled one in disease, tissue and outcome, and the bundled cohort\'s full matrices are not shipped, so a sealed hold-out on the preloaded route is not independent of feature selection. A positive replicated finding would require a second matched RA anti-TNF cohort profiled on comparable platforms, which was not available.

**4.4 Future work**

- Project frozen normalisation and batch-correction parameters onto the reserved validation samples instead of re-processing them together with the discovery samples; add hg38 and EPICv2; live recomputation for bundled genetics routes; provenance for every vertical; job cancellation; proteomics as a third layer.
