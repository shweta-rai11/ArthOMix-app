# Refactoring Notes

Bugs and inconsistencies surfaced while auditing the codebase for the publication-ready reorganization. Per the reorganization's own ground rules, these are **documented, not fixed**, unless fixing was required to keep the reorg itself from breaking the app. One exception is logged below as already fixed.

## Already fixed (not part of the reorg — fixed independently before/during this work)

- **`mod_multi_mofa` function-name mismatch** — `R/multiomics/mod_multi_dataset.R` called `mod_multi_mofa_config/_ui/_server`, but `R/multiomics/mod_multi_mofa.R` only defined `mod_multi_live_config/_ui/_server` (a prior filename rename hadn't updated the internal function names). Fixed in commits `42d8f32` / `680ab0d` on `main`.

## Open — logged, not fixed

- **Duplicate SNF implementation in Multiomics.** `R/multiomics/mod_multi_stratification.R` ("SNF Clustering" stage) calls both its own `sfc_snf_run*` helpers (`snf_clustering_helpers.R`) and `mi_snf_*` helpers (`multiomics_integration_helpers.R`) — the same helpers `mod_multi_integration.R`'s own SNF panel uses. Two parallel SNF code paths feed one UI. Worth consolidating in a future change, out of scope here.
- **Duplicate column-guessing logic in Transcriptomics.** `R/transcriptomics/mod_preprocessing.R`'s local `pp_guess_col()` looks like a near-duplicate of `global.R`'s `guess_column_by_name()` (same signature shape). Worth deduplicating separately.
- **Stale comment in `R/submodules_registry.R`** (as of the original audit) claimed several Methylomics stages ("celltype through diagnostic") were "registry-only placeholder scaffolds ... not built yet." This was already false at audit time — every `mod_methyl_*.R` module (celltype, dmr, wgcna, candidates, featureselection, mr, coloc, diagnostic, validation) has a full implementation. Should be corrected as a documentation fix, independent of this reorg.
- **`tests/testthat/test-methyl-submodules-ui-e2e.R` test-count drift** — at audit time its header comment/`mx_ids` vector referenced an older `MX_MODULES` count/list than what's actually registered. Should be re-verified and updated to match the current registry.
- **`mod_methyl_mr.R` has no dedicated test file** — every other Methylomics stage has at least one `test-methyl-<stage>-*.R`; `mr` doesn't. Coverage gap, not a reorg concern.
- **Crossomics test-file naming inconsistency** — test files use the full prefix `test-crossomics-*` while the other three verticals abbreviate (`test-txn-*`, `test-methyl-*`, `test-multi-*`). Cosmetic; left as-is since renaming test files is outside "pure reorganization" of the app's own `R/` code.
- **Cross-vertical coupling in Methylomics** — `R/methylomics/mod_methyl_biomarkercard.R` calls `cx_harmonize_gene_ids()` (Cross-Omics) and `mp_get_wikipathways_termgene()` (Multiomics) directly. Not a bug, but means Methylomics isn't fully self-contained; worth being aware of when Methylomics is reorganized.
- **Pre-existing E2E test failure, confirmed unrelated to the reorg** — `tests/testthat/test-crossomics-submodules-ui-e2e.R`'s second test ("Dataset -> Expression and Methylation Integration data flow...") fails at the `cx_integration-run_integration` button click with "Cannot find HTML element", both before and after the Cross-Omics folder reorganization (verified by stashing the reorg and re-running against the original code — identical failure). Requires `ARTHOMIX_TEST_EMAIL`/`ARTHOMIX_TEST_PASSWORD` to even run (otherwise `skip_if()`s out), and is also gated behind `skip_on_cran()` so it doesn't run in a normal `testthat::test_dir()` pass. Looks like a UI-timing issue (button not yet rendered when clicked) rather than anything reorg-related. Not fixed here — out of scope.

## Adaptations made during the reorganization itself (not bugs — documented for transparency)

- The task's template top-level `shared/` folder was placed at `R/shared/` (not the app root) so it's picked up by the same `source()`-based loader pattern already used for `R/auth/` (`R/0a_load_auth_modules.R`) — a new `R/0b_load_shared_modules.R` mirrors that pattern for `R/shared/`. Placing it outside `R/` would have required wiring an explicit `source()` call into `global.R` instead, which is a larger and less-consistent change for the same effect.
- Cross-Omics's folder numbering/names follow the vertical's **actual** 3 analytical stages (`integration`, `biomarkerconv`, `mrstage`) plus a Dataset tab, not the task's literal 7-folder template — Cross-Omics genuinely doesn't have a separate Gene-CpG Annotation stage, a separate Pathway Analysis stage, etc. as distinct code.
